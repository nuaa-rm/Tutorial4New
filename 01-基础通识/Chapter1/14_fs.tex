\textbf{“一切皆文件”}

\textbf{主要文件夹及其作用}

/bin：bin 是 Binaries (二进制文件) 的缩写, 这个目录存放着最经常使用的命令。

/boot：这里存放的是启动 Linux 时使用的一些核心文件，包括一些连接文件以及镜像文件。

/dev：dev 是 Device(设备) 的缩写, 该目录下存放的是 Linux 的外部设备，在 Linux 中访问设备的方式和访问文件的方式是相同的。

/etc：etc 是 Etcetera(等等) 的缩写,这个目录用来存放所有的系统管理所需要的配置文件和子目录。

/home：用户的主目录，在 Linux 中，每个用户都有一个自己的目录，一般该目录名是以用户的账号命名的，如上图中的 alice、bob 和 eve。

/lib：lib 是 Library(库) 的缩写这个目录里存放着系统最基本的动态连接共享库，其作用类似于 Windows 里的 DLL 文件。几乎所有的应用程序都需要用到这些共享库。

/opt：opt 是 optional(可选) 的缩写，这是给主机额外安装软件所摆放的目录。比如你安装一个ORACLE数据库则就可以放到这个目录下。默认是空的。

/root：该目录为系统管理员，也称作超级权限者的用户主目录。

/usr：usr 是 unix system resources(unix 系统资源) 的缩写，这是一个非常重要的目录，用户的很多应用程序和文件都放在这个目录下，类似于 windows 下的 program files 目录。

/var：var 是 variable(变量) 的缩写，这个目录中存放着在不断扩充着的东西，我们习惯将那些经常被修改的目录放在这个目录下。包括各种日志文件。

在这些文件夹中，绝大多数目录都包含重要的系统文件，如果随意删除可能会导致系统出错，因此在平时操作时要多加注意。

\begin{exercise}

\end{exercise}

\textbf{04文件与目录管理}

先认识几个常用概念，后面的命令都要用到它们：

\begin{enumerate}
\item 绝对路径：路径的写法，由根目录\enspace /\enspace 写起，例如：/usr/share/doc 这个目录。
\item 相对路径：路径的写法，相对于当前所处的文件夹位置，不是由\enspace /\enspace 写起，例如由 /usr/share/doc 要到 /usr/share/man 底下时，可以写成：cd man
\item \enspace .\enspace ：表示当前目录
\item \enspace ..\enspace ：表示上一级目录
\item 文件类型：分为目录（d），文件（-），链接文件（l），装置文件里可供储存的接口设备（b），装置文件里面的串行端口设备（c）
\item 文件基本属性：分为可读（r），可写（w），可执行（x）。Linux文件属性有两种设置方法，一种是数字，一种是符号。使用数字来代表各个权限时，各权限的分数对照为：r:4，w:2，x:1
\item 文件所有者（user）：表示该文件或目录的拥有者，也就是文件权限中的第一个权限对象（u）。
\item 用户组（group）：表示该文件或目录所属的用户组，也就是文件权限中的第二个权限对象（g）。文件权限通常依次针对文件所有者、所属用户组以及其他用户（others）进行设置。
\item 其他用户（others）：表示既不是文件所有者，也不属于该文件所属用户组的其他用户，是文件权限中的第三个权限对象（o）。
\item 路径名展开（pathname expansion）：属于 Shell（如 Bash）的语法，用于使用通配符匹配文件名。常见的通配符包括 \enspace * \enspace、\enspace ? \enspace 和 \enspace [ ] \enspace。例如：\enspace *.txt \enspace 可以匹配当前目录下所有以 .txt 结尾的文件；\enspace ? \enspace 表示匹配一个字符；\enspace [abc] \enspace 表示匹配 a、b 或 c 中的一个字符。
\end{enumerate}

\begin{conclusion}
硬链接、软链接与复制的区别：

\begin{itemize}
\item 硬链接：与源文件指向同一份数据，删除源文件不影响链接；但不能跨文件系统，也不能给目录创建；
\item 软链接（符号链接）：类似 Windows 的快捷方式，只记录源文件的路径；源文件被删除后链接失效，但可以跨文件系统、可以链接目录；
\item 复制（cp）：得到一份完全独立的新文件，与源文件互不影响。
\end{itemize}
\end{conclusion}

		$  a $		&all，全部的身份 \\
		$  +\enspace -\enspace = $		&对权限加入，除去，设定 \\
		\bottomrule[1.5pt]
	\end{tabular}
\end{center}

使用chmod命令修改文件或目录权限有两种方式。一是用数字类型的权限属性更改，通用形式为：

chmod\enspace [-R]\enspace xyz\enspace 文件或目录

其中 xyz 是三位数字，分别对应所有者、用户组、其他用户的权限，每位数字为该身份 rwx 属性数值（r:4，w:2，x:1）的和。二是用符号类型改变文件权限，通用形式为：

chmod\enspace [身份]\enspace +/-/=\enspace [permissions]\enspace [file name]

\begin{example}
为 \texttt{ex1.py} 的文件拥有者增加可执行权限；再将 \texttt{run.sh} 递归地改为所有人可读可写可执行：
\begin{tbash}
chmod u+x ex1.py
chmod -R 777 run.sh
\end{tbash}
\end{example}

\begin{note}
不要图省事对所有文件都 \texttt{chmod 777}——这相当于把家门钥匙挂在门外，谁路过都能进来逛一圈。权限放得越宽，误操作和恶意篡改的风险越大；脚本只需要给所有者加上执行权限（\texttt{chmod u+x}）就够了。
\end{note}

\begin{conclusion}
vim 三种模式的切换关系：启动后默认处于命令模式；按 \texttt{i} 等键进入输入模式，按 \texttt{ESC} 返回命令模式；命令模式下按 \texttt{:} 进入底线命令模式，执行完命令（如 \texttt{:wq}）后自动回到命令模式。江湖传言，"让新手自己尝试退出 vim"是一种可靠的随机字符串生成方式——卡在任何地方不知所措时，连按 \texttt{ESC} 再输入 \texttt{:q!} 即可强制退出。
\end{conclusion}

\subsubsection{终端里的 IDE：AstroNvim*}

裸装的 vim 对新手不太友好：没有文件树、没有补全、没有语法高亮，突出一个毛坯房，新手进去三秒就想退房。Neovim（nvim）是 vim 的现代化分支，而 AstroNvim 是一套开箱即用的 Neovim 配置——装完就有文件树、模糊搜索、代码补全和漂亮的界面，毛坯房直接变精装，终端里也能有接近 IDE 的体验。

\textbf{安装新版 Neovim}

AstroNvim 需要较新版本的 Neovim（0.10 及以上），而 Ubuntu 22.04 仓库自带的版本太老，因此从官网下载预编译包安装：

\begin{example}
下载并解压 Neovim 到 \texttt{/opt}，顺手装上两个依赖（ripgrep 用于全局搜索，gcc 用于编译语法高亮组件）：
\begin{tbash}
curl -LO https://github.com/neovim/neovim/releases/latest/download/nvim-linux-x86_64.tar.gz
sudo tar -C /opt -xzf nvim-linux-x86_64.tar.gz
sudo apt install ripgrep gcc
\end{tbash}
然后把 \texttt{/opt/nvim-linux-x86\_64/bin} 追加到 PATH（写入 \textasciitilde/.bashrc 或 \textasciitilde/.zshrc，方法见 1.5 节）：
\begin{tbash}
export PATH=$PATH:/opt/nvim-linux-x86_64/bin
\end{tbash}
生效后执行 \texttt{nvim --version} 能看到版本号即安装成功。
\end{example}

\textbf{安装 AstroNvim}

\begin{example}
备份可能存在的旧配置，然后克隆 AstroNvim 模板并启动：
\begin{tbash}
mv ~/.config/nvim ~/.config/nvim.bak
mv ~/.local/share/nvim ~/.local/share/nvim.bak
git clone --depth 1 https://github.com/AstroNvim/template ~/.config/nvim
rm -rf ~/.config/nvim/.git
nvim
\end{tbash}
\end{example}

首次启动会自动下载安装全部插件，泡杯茶等它跑完，看到欢迎界面就大功告成了。如果之前没有安装过 nvim，前两行备份命令报"文件不存在"属正常现象，忽略即可。

\begin{note}
第四步的 \texttt{rm -rf} 是为了去掉模板自带的 git 仓库信息，让这个配置目录变成你自己的仓库（方便日后提交和同步个人配置）。路径请照抄，不要自行发挥。
\end{note}
