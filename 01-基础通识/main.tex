\section{本章小结}
本章围绕"装好系统 → 用好系统 → 护好系统"这条主线展开：

\begin{itemize}
\item \textbf{安装与维护}：双系统安装的四个流程（分区、制作启动盘、安装、设置）需要亲手走一遍；Timeshift 保护系统文件与设置，个人资料另备份；恢复前检查快照范围、目标与新数据，不能把快照当成整盘无损回档。系统扩容、grub 美化、卸载重装属于选修内容，用到时再回来查即可。
\item \textbf{命令行基础}：目录结构、"一切皆文件"与挂载是必须理解的概念；文件管理（ls/cp/mv/rm）、查找（find/grep）、重定向与管道、vim 基本操作是每天都要用的基本功，要求熟练；各命令的参数不必死记，会用参数表和 man 手册查即可。
\item \textbf{shell 与环境变量}：会编写并运行简单的 shell 脚本；理解 PATH 的作用，区分普通变量、export 与 source，按 Shell 启动方式核对配置读取；日常交互 Bash 配置优先放在 \textasciitilde/.bashrc。
\item \textbf{git}：理解工作区、暂存区、本地版本库、远程仓库四个区域的流转关系，熟练掌握 add、commit、push、pull 的日常闭环，会写基本的 .gitignore。
\item \textbf{conda}（选修）：会创建、激活、退出和删除虚拟环境，配环境时先在虚拟环境中试错。
\item \textbf{图形开发工具}：安装 CLion 与 VS Code，识别菜单、项目树、工具栏、输出面板和状态栏；用同一份 CMake 工程完成配置、构建、运行和断点调试，能区分编辑器与编译工具链。
\item \textbf{串口通信}：识别队内 USB CDC ACM 设备及所属组，用 udev 为目标板绑定固定别名；区分 USB 通信与 UART 参数的含义，通过约定的测试协议验证收发；按设备、权限、命名、占用和协议逐层排错。
\end{itemize}

完成本章验收后，就可以揣着新装好的系统进入第 2 章了。配置环境的道路还会不断延伸——不要停下来啊，第 2 章现代 C++ 见。

\section{本章小结}
本章围绕"组织数据 → 组织函数 → 组织内存 → 组织计算"这条主线展开：

\begin{itemize}
\item \textbf{类与面向对象}：类的三大成员（数据成员、成员函数、构造/析构函数）和三种访问限定符是天天要用的基本功，要求熟练；函数重载、运算符重载、继承与多态是阅读和编写类代码的必备能力；模板只需掌握最基本的函数模板和类模板写法，遇到变参模板等进阶内容会查文档即可。
\item \textbf{lambda、引用与移动}：lambda 的捕获列表（值捕获 vs 引用捕获）和 \texttt{std::function} 承接要熟练使用，回调和排序比较器里到处都是它；左值/右值、两种引用与 \texttt{std::move}/\texttt{std::forward} 是本章最容易混淆的部分，值类别属于表达式，有名字的右值引用表达式仍是左值；move 本身不搬数据，forward 保留传入的值类别。用实际调用记录核验，不能把取地址当作通用定义。
\item \textbf{智能指针}：掌握 \texttt{unique\_ptr}（独占）、\texttt{shared\_ptr}（计数共享）、\texttt{weak\_ptr}（观察不占有）的分工，默认优先 \texttt{make\_unique}/\texttt{make\_shared}；循环引用的成因和用 \texttt{weak\_ptr} 破解的方法必须理解。
\item \textbf{STL}：\texttt{vector} 的常用成员函数和扩容机制要熟练；队列、堆栈、映射等容器知道各自解决什么问题、会去 cppreference 查用法即可；迭代器失效是新手重灾区，删除元素时牢记用 \texttt{erase} 的返回值更新迭代器。
\item \textbf{多线程与内存}：会创建线程，使用 \texttt{mutex}/\texttt{lock\_guard}、共享锁、原子变量和条件变量；能用 \texttt{future}、\texttt{promise}、\texttt{async} 传递异步结果；理解生产者—消费者、读者—写者、哲学家进餐和死锁；进程内存分区（代码/常量/静态/堆/栈）和栈帧机制是理解悬垂指针、栈溢出等经典 bug 的地基，务必建立图景。
\end{itemize}

本章验收通过后，恭喜你已经掌握了阅读现代 C++ 工程代码的主要语法设施。下一章我们来看看这些代码是如何被编译器组装成可执行文件的——CMake 见。

本章安排 12 道自测题：核心语法、容器与并发都要覆盖，最后两题补模板和寿命判断；现场验收则检查独立运行与解释，不重复抄题。
\begin{problemset}
\item \label{prob:v1-cpp-1} 说出 \texttt{public}、\texttt{private}、\texttt{protected} 三种访问限定符的区别，并说明基类的 \texttt{private} 成员能否被派生类直接访问。

\item \label{prob:v1-cpp-4} 解释左值与右值的区别，分别判断 x、x+1、std::move(x) 和有名字的右值引用表达式，说明取地址法有什么边界。

\section{本章小结}
这一章，我们把代码一步步变成了能运行的程序。回头看，最常用的是这几件事：
\begin{itemize}
    \item \textbf{看懂编译过程}：说清预处理、编译、汇编和链接各做什么，能区分声明与定义、头文件与目标文件、静态库与动态库。四步命令亲手跑过即可，日常交给构建工具。
    \item \textbf{跑通 CMake 工作流}：用 \texttt{cmake -S/-B} 配置，用 \texttt{cmake --build} 构建，再用 \texttt{cmake --install} 安装。这几条要练熟，源码目录和构建目录也要分开。
    \item \textbf{写清目标与依赖}：先用 \texttt{add\_executable} 或 \texttt{add\_library} 创建目标，再给它设置头文件路径和链接依赖。这部分要会写，也要能说出哪些配置只给自己用，哪些会传给下游。
    \item \textbf{按阶段排错}：先判断卡在配置、编译、链接还是运行，再查相应的路径、实现或依赖。参数细节、自定义模块和 ROS2 的构建约定，用到时会查就行。
\end{itemize}
现在拿一份构建文件，试着说出它要生成什么、依赖什么、怎样运行验证。能说清，也能亲手跑通，就可以带着这些基本功去卷二了。
以后再遇到满屏报错，至少知道从哪里查起——这已经比对着终端许愿靠谱多了。

\begin{problemset}
\item\label{prob:v1-build-1} （基础）写出从 \texttt{demo.cpp} 到可执行文件的四个阶段及其中间文件扩展名，并说明 \texttt{g++ -c demo.cpp} 停在哪一步。
\item\label{prob:v1-build-2} （基础）你把项目命名为 \texttt{training}，把可执行目标命名为 \texttt{viewer}。这两个名字分别管什么？终端出现 \texttt{Generating done} 时，程序已经编译好了吗？
\item\label{prob:v1-build-3} （基础）程序需要 \texttt{main.cpp} 和 \texttt{score.cpp}，头文件放在 \texttt{include} 目录。你已经设置了头文件搜索路径，还需要把 \texttt{score.cpp} 加进目标吗？说说理由。
\item\label{prob:v1-build-4} （基础）比较 \texttt{add\_library(score STATIC score.cpp)}、显式写 \texttt{SHARED} 和省略类型三种写法的含义。
\item\label{prob:v1-build-5} （基础）你用 \texttt{add\_library(score STATIC score.cpp)} 创建了库，但没定义名为 \texttt{score} 的变量。链接时写 \texttt{score} 和 \texttt{\$\{score\}}，结果一样吗？
\item\label{prob:v1-build-6} （基础）安装规则的目标目录为 \texttt{bin}，安装前缀为 \texttt{/home/student/demo-stage}。目标 \texttt{viewer} 会安装到哪里？只运行安装命令能否替代构建？
\item\label{prob:v1-build-7} （基础）库需要两个头文件目录：一个是库自己和使用这个库的程序都要用的，另一个只供库内部使用。它们分别该设成什么作用域？\texttt{INTERFACE} 又适合什么情况？
\item\label{prob:v1-build-8} （基础）\texttt{find\_package(OpenCV REQUIRED)} 在配置阶段失败。它会自动安装 OpenCV 吗？自行安装 OpenCV 后，\texttt{OpenCV\_DIR} 应指向哪类目录？
\item\label{prob:v1-build-9} （提高）你把 \texttt{SAVE\_OUTPUT} 从 \texttt{OFF} 改成 \texttt{ON}，\texttt{print\_var(SAVE\_OUTPUT)} 已经打印出 ON；配置完成后就运行原程序，却没看到新提示。请按模块函数、CMake 变量、编译宏、可执行文件的顺序，解释中间漏了哪一步。
\item\label{prob:v1-build-10} （实践）观察一次“哪些文件需要重新编译”。在静态库工程中，先不改任何文件，连续构建两次；然后只改 \texttt{src/armor.cpp} 中的乘数，再构建一次。用 \texttt{--verbose} 保存后两次构建的输出，看看各自做了哪些工作。最后把乘数改回来。
\end{problemset}

\section{本章验收}
由考核者现场检查以下任务。可查阅本章参数表，重点是能独立完成操作，并根据实际输出解释结果。
章末习题中的增量构建日志用于自测；这里检查从拿到源码到交付程序的完整过程。
\begin{enumerate}
    \item \textbf{独立构建}：在新的练习目录中，只保留自己编写的头文件、源文件和 \texttt{CMakeLists.txt}，从空构建目录开始配置、构建并运行装甲板程序。现场指出源码目录、构建目录、库目标和可执行目标，展示实际输出 \texttt{score=30}。
    \item \textbf{调整工程}：按考核者给定的新目标名修改构建描述，在另一个空构建目录中构建。先说出预期产物的位置，再运行验证；说明每处目标名修改的用途。
    \item \textbf{定位故障}：由考核者在工程副本中设置一个故障，例如源文件路径拼错、函数声明与定义不一致，或把 \texttt{OpenCV\_DIR} 指向不含包配置文件的目录。先展示实际错误并判断失败阶段，再修复并重新构建。若错误配置没有触发失败，应说明依赖是否从其他路径被找到，不能把猜测当作错误记录。
    \item \textbf{安装与交付}：使用静态库版本，将程序安装到考核者指定的练习目录，从该目录启动。提交源码和一份简短的构建说明，写明工具版本、配置与构建命令、安装位置和预期输出，使另一位同学能从源码复现。
    \item \textbf{接入外部依赖}：在 Ubuntu 桌面环境中构建图像读取示例，使用考核者提供的图片，展示窗口与实际尺寸输出。指出查找 OpenCV、设置包含目录和链接库分别是哪条配置，并解释三者的用途。
\end{enumerate}
\begin{note}
验收以本次构建成功和实际运行输出为依据，不能只展示旧构建目录中的可执行文件。
若暂时没有图形桌面，可先核验 OpenCV 的查找与构建，但图像窗口演示须注明待补验；ROS2 选读片段不计入本章验收。
\end{note}
