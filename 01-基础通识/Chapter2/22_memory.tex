前面我们已经见过局部变量和智能指针。这时候很容易产生一个疑问：变量离开作用域就消失，为什么它指向的对象有时还在？先把“保存地址的变量”和“地址所指的对象”分开看，它们的寿命可以不同。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.82\textwidth]{process-memory_revised.pdf}
    \caption{Linux 进程虚拟地址空间的简化示意；大小、位置和增长方向不是 C++ 语言保证}
    \label{fig:内存分区}
\end{figure}

如图\ref{fig:内存分区}，我们通常借助代码、只读数据、静态数据、动态分配和线程栈来理解程序。这里画的是一个\textbf{进程的虚拟地址空间}，不是把机器的物理内存切成这几块。操作系统、链接器、优化和地址随机化都会影响实际布局，先用它建立图景，再回到 C++ 的存储期规则判断寿命。

\textbf{代码和只读数据。} 可执行代码通常在代码段，字符串字面量等只读数据通常在只读数据段。不要看到 const 或 constexpr 就判断“一定在常量区”：局部 const 对象仍可以有自动存储期，优化后也可能放在寄存器中，甚至没有单独的存储位置。

\textbf{静态数据。} 全局变量、命名空间作用域的 static 变量、静态局部变量和类的静态数据成员具有静态存储期。全局变量并不比 static 变量活得短；函数内 static 的动态初始化通常在第一次执行到声明时发生，以后调用会继续使用同一对象。
这里顺带分清三件事：作用域决定在哪里能写这个名字，链接决定跨文件的名字是否指同一个实体，存储期决定对象的存储活多久。文件里的 static 可以限制内部链接，不能把它简单解释成“所有地方都能用的全局变量”。

\textbf{动态分配与堆。} new 创建动态存储期对象，delete 结束它的寿命并释放存储；智能指针把这件事交给所有权管理。vector 这个变量可以是局部变量，而它保存元素的缓冲区通常是动态分配的，不能只看变量名就判断整份数据“在栈上”。

\textbf{自动存储期与线程栈。} 普通局部对象通常随作用域退出而销毁，典型实现会用线程栈或寄存器保存它们。程序员可以用作用域安排寿命，编译器负责实现；栈大小由环境决定，不固定为 2 MB。Linux 中可用 \texttt{ulimit -s} 查看当前 Shell 的栈限制（通常以 KiB 显示），它不直接给出所有线程的实际栈大小。

\Needspace{10\baselineskip}
\begin{example}
项目 \path{examples/memory-lifetime-demo} 中只有 \texttt{main.cpp} 和运行说明。我们让函数返回独占指针，观察局部对象与动态对象分别在什么时候析构：
\lstinputlisting[language=C++,numbers=left,numberstyle={\color{gray}\tiny}]{examples/memory-lifetime-demo/main.cpp}
\begin{tbash}
cd examples/memory-lifetime-demo
g++ -std=c++17 -Wall -Wextra main.cpp -o /tmp/memory-lifetime
/tmp/memory-lifetime
\end{tbash}
先构造 local，再构造 dynamic；函数返回前 local 被析构，主函数仍能使用 dynamic，最后 reset 才使它析构。函数里的指针变量离开作用域了，但所有权已经交到调用方，对象并没有随它一起消失。
\end{example}

\begin{note}
不能返回局部对象的地址或引用后继续使用：对象已经销毁，地址即使看起来没变，也不再代表一个活着的对象。不要通过“运行没崩”判断安全。返回对象的值或返回有明确所有权的智能指针，才能把寿命关系说清楚。
\end{note}

\textbf{函数调用与递归。} 典型实现中，一次调用会有自己的栈帧，保存参数、局部状态和返回信息。新栈帧不会把旧栈帧的数据覆盖掉；返回时继续执行调用者。调用者仍能通过传入的指针或引用让被调函数访问它的对象。编译器可能内联或优化调用，下面画的是帮助理解的简化模型。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{recursion-stack_revised.pdf}
    \caption{递归调用逐层进入、逐层返回；每次调用有独立的局部状态}
    \label{fig:栈递归}
\end{figure}
图中仍沿用 $f(1)=3$、$f(n)=2f(n-1)+1$ 的例子，返回值依次是 3、7、15、31。递归必须有终止条件；调用太深可能耗尽栈，不能把它当作可以无限增长的容器。

\Needspace{10\baselineskip}
\begin{example}
同一项目的 \texttt{recursion.cpp} 把图里的调用顺序打印出来。每次进入先打印自己的 n，返回时再打印这一层的结果：
\lstinputlisting[language=C++,numbers=left,numberstyle={\color{gray}\tiny}]{examples/memory-lifetime-demo/recursion.cpp}
\begin{tbash}
g++ -std=c++17 -Wall -Wextra recursion.cpp -o /tmp/recursion-demo
/tmp/recursion-demo
\end{tbash}
先依次进入 4、3、2、1，再依次返回 3、7、15、31。外层的 n 没有被内层覆盖；它还要等内层返回后继续计算。本例只调用四层，别为了观察栈溢出把递归深度随手改得很大。
\end{example}

\begin{conclusion}
先看对象的存储期与所有权，再借助内存图理解实现。局部指针的寿命不等于所指对象的寿命；引用和普通指针不会自动延长任意对象的寿命；把地址交给线程前，还要确认线程结束之前对象仍在、并发访问已经同步。
\end{conclusion}
