# 教材章节编写与改造规范

读者是零基础或基础薄弱的本科新生。写作目标：让读者能照着教材独立完成任务，并通过练习确认自己学会了。语言使用简体中文，代码注释也用简体中文，术语首次出现给中英文对照。完整版参考文档见 `templates/chapter-guide.md`。

## 章节标准结构

### 1. 章首：内容提要（必须）

`\chapter{...}` 之后立即写 `introduction` 环境，固定三条：

```latex
\begin{introduction}
  \item 学习目标：……（用可验证的行为动词，如"编写""完成"，避免"了解""理解"）
  \item 建议学时：……
  \item 本卷边界：……（说明本章不讲什么、指向哪一卷）
\end{introduction}
```

### 2. 小节正文：讲解 → 示例 → 练习

1. **概念讲解**：先讲"做什么、为什么"，再讲"怎么做"。命令/语法类内容先给通用形式（如 `free [options]`），再用表格列参数，不要把参数写死在语法行里。
2. **示例**：可操作的知识点必须有完整可运行示例，用 `example` 环境包裹：

```latex
\begin{example}
统计当前目录下各子目录的磁盘占用：
\begin{tbash}
du -h --max-depth=1 .
\end{tbash}
\end{example}
```

3. **随堂练习**：核心小节节末用 `exercise` 环境出 1~2 道小题（5~15 分钟可完成），与刚讲的内容强绑定：

```latex
\begin{exercise}
使用 find 在家目录下查找所有 7 天内修改过的 \texttt{.py} 文件。
\end{exercise}
```

### 3. 困难知识点：阶段性小结（按需）

符合以下任一条件的知识点，讲完后必须加 `conclusion` 小结（对比表格或 3~5 条要点，不超过半页）：
- 涉及 3 个以上易混淆概念（如硬链接 vs 软链接）；
- 初学者常见错误已知（如 `rm -rf` 误用）；
- 内容跨多个小节才讲完。

易错点和注意事项随时用 `note` 环境插入正文。

### 4. 章末三件套（必须，按此顺序）

```latex
\section{本章小结}      % 知识地图：学了什么、如何串联、哪些要熟练哪些只需会查，≤1 页

\begin{problemset}      % 自动排版"第X章 练习"，带目录条目
\item （基础题，每个核心小节至少 1 题）
\item （提高题，组合多个知识点）
\item （实践题，需在真实环境完成并验证）
\end{problemset}

\section{本章验收}      % 保留现有风格：可检查、可演示的操作性任务
```

分工：`problemset` 习题用于自测知识点（有标准答案），"本章验收"用于人工考核操作能力，两者不重复出题。习题量每章 5~10 题。若提供答案，用 `solution` 环境紧跟题目（模板 `result=noanswer` 可全局隐藏）。

## 模板环境速查

| 用途 | 环境 | 说明 |
|---|---|---|
| 章首提要 | `introduction` | 双栏，只放 `\item` |
| 示例 | `example` | 带章内编号，可接 `[说明]` |
| 随堂练习 | `exercise` | 带编号 |
| 章末习题 | `problemset` | 内部直接写 `\item` |
| 注意/易错 | `note` | 带警示图标 |
| 小结 | `conclusion` | 蓝色标题块 |
| 参考答案 | `solution` | 可被全局隐藏 |
| 代码 | `tcode`/`tcpp`/`tpython`/`tbash` | 带边框行号语法高亮，转义符为反引号 |

其他约定：
- 正文层级从 `\subsubsection` 写起（preamble 已映射），不用 `\section`/`\subsection`，层级由 `main.tex` 控制；
- 表格用 booktabs 三线表（`\toprule[1.5pt]`/`\midrule[1pt]`/`\bottomrule[1.5pt]`），表头"语法/参数/命令 & 作用"；
- 图片 `\begin{figure}[H]`，宽 `0.7~0.9\textwidth`，必须有 `\caption` 和 `\label`；
- 命令用 `$...$` 包裹、`\enspace` 分隔，与相邻表格风格一致。

## 写作风格

1. 命令/语法首次出现时先说清"它解决什么问题"；
2. 先通用语法、后参数表、再具体示例；
3. 参数表只列最常用 5~10 项，尾部注明"其余参数请查阅 man 手册"；
4. 危险操作（`rm -f`、分区、格式化等）必须用 `note` 警示；
5. 外部资源链接放 `note` 中，用 `\url{}`；
6. 同一知识点只在一处展开，其他处用"见 X 节"引用（DRY）。

## 语言口吻

1. **简洁直白**：句子短、用词日常，避免学术腔和长定语从句。能用一句话说清的不用两句；能让初学者一遍看懂是第一标准。
2. **可以风趣**：允许在讲解、示例和习题中适当开玩笑、用梗（包括二次元梗），让读者感到教材是"学长写的"而不是"标准文档抄的"。例如：
   - 讲 `rm -rf` 时："这条命令删库跑路一气呵成，使用前请三思——你的存档没有读档功能。"
   - 讲 git 合并时："分支 A 和分支 B 表示：我们联合！"
   - 讲"一切皆文件"时："你以为是 U 盘设备？其实是我文件哒！"
   - 讲 vim 退出时："江湖传言，让新手自己尝试退出 vim 是一种可靠的随机字符串生成方式。"
   - 示例文件名、习题情景可以用读者熟悉的游戏/动漫元素。
3. **浓度放宽但有底线**：梗是调味料不是主菜——
   - 只出现在段落开头/结尾的调味句、`note`、`conclusion` 收尾或习题情景里，**不得**进入知识点解释本体、参数表、代码注释（保持可检索性和严肃性）；
   - 不设每小节/全章数量硬上限，以"读着不累、像学长在聊天"为度；同一个小节里梗不要扎堆，讲透一个再放下一个；
   - 梗要通用易懂，不依赖冷门作品；不用任何可能冒犯读者的梗；
   - 危险操作警示（`rm -f`、格式化等）可以幽默但警示信息本身必须清晰无歧义。
4. 口吻统一为"学长带学弟"：平等、鼓励、偶尔吐槽，不说教、不端着。

## 改造现有章节检查清单

最小侵入原则：不打乱原有小节顺序和内容，缺什么补什么。

- [ ] 章首 `introduction` 三条齐全（目标/学时/边界）？
- [ ] 每个核心小节至少一个 `example` 可运行示例（散文式举例改造为 `example`）？
- [ ] 命令遵循"先命令、后参数表"结构？（参考卷一 14_fs.tex 的 02 节）
- [ ] 核心小节节末有 1~2 道 `exercise`？
- [ ] 困难知识点有 `conclusion` 小结？
- [ ] 已知易错点有 `note` 警示？
- [ ] 章末有 `problemset`（5~10 题，覆盖各小节，分基础/提高/实践）？
- [ ] 有"本章小结"（≤1 页）？
- [ ] "本章验收"保留且与习题不重复？
- [ ] `xelatex main.tex` 编译两遍无错误？

## 输出要求

- 直接输出修改后的完整 `.tex` 或 diff，不省略中间段落；
- 不改 `main.tex` 的层级映射逻辑和模板文件；
- 完成后说明：新增了哪些结构要素、改造了哪些内容、哪些位置留待人工补充。
