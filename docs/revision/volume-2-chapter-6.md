## 环境、实际结果与边界

证据为 [volume-2-chapter-6-runtime.json](evidence/volume-2-chapter-6-runtime.json)，记录源码散列、命令、退出状态和输出。`scripts/verify_cuda_examples.py` 完整执行 52 条记录；随后实际补查隐藏设备时的管理工具，单独记录为第 53 条，没有为新增一条只读查询重复其他已通过实验。

环境为 Distrobox ubuntu2404 / Ubuntu 24.04.5 / GCC 13.3 / CMake 3.28.3，RTX 3070 Ti Laptop、宿主驱动 615.71.09、计算能力 8.6。只在 Ubuntu 容器增加 cuda-keyring 与 cuda-compiler-12-6、cuda-cudart-dev-12-6、cuda-sanitizer-12-6 及其开发依赖，安装模拟为 0 升级/15 新包/0 删除，没有安装宿主驱动。compiler 元包 12.6.3，nvcc 12.6.85，cudart/sanitizer 12.6.77；实际 runtime API=12060、driver API=13040，版本不同仍实际运行成功。安装用显式路径，没有改用户全局 PATH 或 LD_LIBRARY_PATH。

- 六目标 Release 构建通过，同一源码的 g++/nvcc 直接构建也通过；架构 86 来自本设备 8.6，不承诺能照搬到其他 GPU。
- 向量输入随索引变化，默认 1048579 / 256 检查全部结果；257 / 128 与 256、10 / 4 等边界变体通过。无效长度、字符串后缀和块大小被拒收。4096 的三个设备数组共 49152 字节，上传 32768、下载 16384。
- 513 / 256 共享 partial=896/896/0，总和 1792；257 / 128 为 448/448/0、896。零填充与无条件块内屏障都实际执行。
- 正常 vec_add 的 memcheck 与 shared_sum 的 memcheck/racecheck/synccheck 均为 0 errors。launch 检出非法配置，execute 在同步检出设备断言，各返回 1；故意越界只在 memcheck 下运行，报告非法写入及同步失败，工具返回 9。新的正常进程运行成功。
- 去掉共享核屏障的临时变体实际被 racecheck 检出冲突，返回 9。正确输出、启动检查、访问检查和同步检查没有互相冒充。
- `CUDA_VISIBLE_DEVICES=''` 时设备查询报告 no CUDA-capable device is detected、返回 1，CPU 程序仍运行；恢复默认可见性后查询和分配成功。隐藏环境下 nvidia-smi 仍报告该 GPU，所以管理查询不能代替应用访问验证。
