# Zenoh 中间件补充与验收（2026-10-03）

在卷二第一章现有“中间件怎么选”内补入 **Zenoh / rmw_zenoh_cpp**，保持 Ubuntu 22.04 / ROS2 Humble，以及 **1440×1080@250 Hz（宽×高）** 的相机场景。新增内容与已有 Fast DDS、Cyclone DDS 共用同一个 image-path-demo，不新建另一套图像节点。核心 C++、接口与 Launch 未变，运行复用前轮实际构建的 Release 产物；修改的是调度记录器、说明、习题及题解。

正文 [A_ros2_image_path.tex](../../02-专项技术栈/chapters/A_ros2_image_path.tex) 包含三种实现的比较、两终端安装/路由器/组件示例、自动对照、配置与故障排查、Zenoh 共享内存和借出 API 的区别，以及 memlock 失败→检查→缩小实验池→复测的完整操作。运行说明见 [项目 README](../../02-专项技术栈/examples/ros2/image-path-demo/README.md)，共同实测表在 [A_ros2_image_results.tex](../../02-专项技术栈/chapters/A_ros2_image_results.tex)。已有中间件练习与借出练习增加 Zenoh，章末小结/验收和参考答案同步；全章仍为 18 道随堂练习、14 道章末题。

## 实际运行

在已有 NVIDIA 集成的 ubuntu2204 Distrobox 中，直接安装仓库包 ros-humble-rmw-zenoh-cpp 与 ros-humble-zenoh-cpp-vendor，均为 **0.1.9**。没有升级既有 ROS 包。记录器为每轮 Zenoh 启动独立本机路由器，默认只监听 127.0.0.1:17447，启动前检查占用，正常结束后仅关闭自身进程组；CPU/RSS 包括自身路由器。手动默认参数复核使用 7447 端口。实际版本、默认配置、memlock、完整原始日志与数据放在 [runtime](evidence/ros2-zenoh-20261003-runtime/summary.json)。

| 实验 | 实际结果与证据 |
|---|---|
| 小图像三种布局，3 轮 | 64×48 BGR8、25 Hz、50 帧，均收到 50 帧，首尾像素检查无失败；intra 地址全部匹配。[small](evidence/ros2-zenoh-20261003-runtime/small/results.json)。 |
| 大图像默认三种布局，9 轮 | 1440×1080 BGR8、250 Hz、1000 帧，三布局各重复三次，全部收到 1000 帧；best_effort、深度 5、两秒排空、SHM 关闭。[bgr250](evidence/ros2-zenoh-20261003-runtime/bgr250/results.json)。 |
| 48 MiB SHM 池，3 轮 | 启用配置但 memlock 为 8 MiB，节点日志出现 Error creating lazy ShmProvider / OS error 12。虽然收齐 1000 帧，但属于共享池分配失败后的回退记录，不能算作 SHM 生效。未纳入教材性能表。[fallback](evidence/ros2-zenoh-20261003-runtime/shm-48mib-fallback/results.json)。 |
| 6 MiB SHM 池，3 轮 | 只改变这项独立对照的共享内存配置，separate、1000 帧、三轮均完整交付，日志无前述共享池错误。[shm-6mib](evidence/ros2-zenoh-20261003-runtime/shm-6mib/results.json)。 |
| 低频共享段诊断，1 轮 | 1440×1080、25 Hz、20 帧全部交付；详细日志记录 Source 创建 6291456 字节共享段、Sink 打开同一段（ID 625444930）。支持共享池实际创建/跨进程访问，未逐帧跟踪证明 250 Hz 全程只走 SHM；诊断日志不混入性能表。[diagnostic](evidence/ros2-zenoh-20261003-runtime/shm-diagnostic/rmw_zenoh_cpp-separate-1.log)。 |
| 默认参数复核，1 轮 | intra、64×48、25 Hz、100 帧，全部交付，地址全部匹配。[manual-default](evidence/ros2-zenoh-20261003-runtime/manual-default/results.json)。 |
| DDS 记录器回归，3 轮 | Fast DDS 三布局、20 帧全部交付，验证扩展后原有 DDS 路径与进程清理。[dds-smoke](evidence/ros2-zenoh-20261003-runtime/dds-smoke/results.json)。 |
| 借出探测，2 轮 | Zenoh 关闭/开启 SHM 的 Float64/Image 均为 0/0，发布调用返回成功并显示本地分配器回退。没有订阅端借出验收。[loans](evidence/ros2-zenoh-20261003-runtime/loans.json)。 |

本轮共 **23 组图像运行 + 2 组借出探测**。图像内容/交付与正常退出检查通过；其中默认 48 MiB 的三轮共享池初始化失败明确保留为回退案例，不能以消息送达冒充 SHM 功能通过。历史 DDS 对照保持原始数值，新增 Zenoh 按同机同消息/QoS 条件追加，固定顺序不是普遍排名。所有实验均为合成图像，没有接入实际相机、GPU 图像链路、第二台主机或无线网络。

| Zenoh 布局 | SHM | 实际发送 Hz | 实际接收 Hz | 接收比例 | P95 ms |
|---|---|---:|---:|---:|---:|
| separate | 关闭 | 250.1 | 250.3 | 100.0% | 3.243 |
| same | 关闭 | 250.0 | 250.2 | 100.0% | 0.913 |
| intra | 关闭 | 250.0 | 250.0 | 100.0% | 0.029 |
| separate | 开启，6 MiB | 250.0 | 250.4 | 100.0% | 1.822 |

每项分别取三轮中位数。延迟为填充后/publish 前至订阅回调入口的同机单调时钟差，不含曝光、填充、算法与控制。6 MiB 只能容纳很少的在途大图像，作为当前环境演示，不作为一般部署推荐。所用实现会调用 mlock，必须同时核对 /dev/shm 与锁定内存上限；未改动系统级 memlock。测试结束后无遗留组件容器或 Zenoh 路由器，见 cleanup.json；端口占用保护另实际验证，既有监听服务未被触碰，见 port-conflict-check.json。
