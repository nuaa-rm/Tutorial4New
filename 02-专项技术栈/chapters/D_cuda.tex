\subsubsection{CUDA 简介}

2006 年，NVIDIA 发布 \textbf{CUDA}（Compute Unified Device Architecture）：
一套在 NVIDIA GPU 上做通用并行计算的平台与编程模型。
与必须把计算映射到图形 API 不同，CUDA 把 GPU 当作数据并行计算设备，
用接近 C/C++ 的语法编写在设备端执行的函数（\textbf{kernel}）。

视觉组相关用途主要包括：
\begin{itemize}
    \item 图像预处理、滤波、几何变换等可高度并行的算子；
    \item 深度学习训练与推理的底层加速（PyTorch、TensorRT 等均依赖 CUDA）；
    \item 自定义高性能算子（当库函数无法满足延迟要求时）。
\end{itemize}

配套库常见有：运行时 API、\textbf{cuBLAS}（线性代数）、\textbf{cuFFT}（FFT）、
\textbf{cuDNN}（深度网络原语）等。
\begin{note}
官方编程指南：\url{https://docs.nvidia.com/cuda/cuda-programming-guide/}。
\end{note}


\begin{example}
一幅 640×480 图像有 307200 个像素，逐像素加亮可独立处理每个像素，适合并行。若每个像素依赖前一个像素的新结果，则不能直接照搬这种分工。
\end{example}

\begin{exercise}
对“逐像素阈值”和“累计前缀和”分别说明是否存在跨元素依赖。
\end{exercise}

\subsubsection{异构计算：Host 与 Device}

GPU 一般不独立运行完整操作系统任务，而是作为 CPU 的协处理器。
CPU 端称为 \textbf{host}，GPU 端称为 \textbf{device}，二者经 PCIe 等总线连接。
典型流程：
\begin{enumerate}
    \item Host 分配设备内存（\texttt{cudaMalloc}）；
    \item 将数据从 Host 拷到 Device（\texttt{cudaMemcpy}）；
    \item 启动 kernel 在 GPU 上计算；
    \item 将结果拷回 Host（\texttt{cudaMemcpy}）；
    \item 释放设备内存（\texttt{cudaFree}）。
\end{enumerate}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.85\textwidth]{Host-Device.png}
    \caption{CPU--GPU 异构架构示意}
    \label{fig:host_device}
\end{figure}

数据搬运开销不可忽视：若计算量很小而拷贝很重，整体可能比纯 CPU 更慢。
工程上应尽量减少往返拷贝，或把多步处理串在 Device 侧完成。

\begin{example}
三个长度为 1024 的 float 数组共需 12288 字节设备内存。上传两个输入、下载一个输出，总搬运量也是 12288 字节；如果连续执行多个算子，中间结果留在设备端可减少往返。
\end{example}

\begin{exercise}
长度改为 4096，元素类型仍为 float，分别计算设备内存和一次完整流程的拷贝字节数。
\end{exercise}

\subsubsection{CUDA 编程基础}

以下内容依据 NVIDIA \emph{CUDA Programming Guide} 中 Intro / Writing Kernels 章节整理。

\paragraph*{线程层次：Thread、Block、Grid}

Kernel 启动时创建大量线程，组织为：
\begin{itemize}
    \item \textbf{Thread}：执行同一段 kernel 代码的基本单位，通过内置变量区分各自数据；
    \item \textbf{Block}：一组可协作的线程，共享一块 \textbf{shared memory}，可用 \texttt{\_\_syncthreads()} 同步；
    \item \textbf{Grid}：若干 Block 的集合，分布在多个 SM（Streaming Multiprocessor）上执行。
\end{itemize}

核内常用内置变量：\texttt{threadIdx}、\texttt{blockIdx}、\texttt{blockDim}、\texttt{gridDim}（可达三维）。
一维全局下标常写为：
\begin{tcode}
int i = blockIdx.x * blockDim.x + threadIdx.x;
\end{tcode}

启动语法（triple chevron）：
\begin{tcode}
kernel<<<gridDim, blockDim>>>(args...);
// 或 dim3 grid(gx, gy); dim3 block(bx, by);
// kernel<<<grid, block>>>(...);
\end{tcode}
第一参数为 Grid 维度，第二参数为每个 Block 的线程数。
Block 大小常取 128、256 等，需结合占用率与问题规模调试。

编译器将 CUDA 源文件构建为程序，通用形式为 $nvcc\enspace [OPTIONS]\enspace INPUT$。
\begin{center}
\begin{tabular}{lp{0.58\textwidth}}
\toprule[1.5pt]
参数 & 作用 \\
\midrule[1pt]
\texttt{-o FILE} & 指定输出文件 \\
\texttt{-O2} & 启用常用优化级别 \\
\texttt{-std=c++17} & 选择 C++ 语言标准 \\
\texttt{-arch=ARCH} & 指定目标 GPU 架构，按设备填写 \\
\texttt{--version} & 查看编译工具版本 \\
\bottomrule[1.5pt]
\end{tabular}
\end{center}
其余参数请查阅 nvcc 帮助或对应版本手册。

\paragraph*{第一个例子：向量加法}

\begin{example}
将完整程序保存为 vec\_add.cu，检查全部元素而不只看首元素。
\begin{tcode}
#include <cuda_runtime.h>
#include <cstdio>
#include <cstdlib>

#define CUDA_CHECK(call) do { \
    cudaError_t e = (call); \
    if (e != cudaSuccess) { \
        fprintf(stderr, "%s\n", cudaGetErrorString(e)); \
        std::exit(1); \
    } \
} while (0)

__global__ void vecAdd(const float* A, const float* B, float* C, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) C[i] = A[i] + B[i];
}

int main() {
    const int n = (1 << 20) + 3;
    size_t bytes = n * sizeof(float);
    float *hA = new float[n], *hB = new float[n], *hC = new float[n];
    for (int i = 0; i < n; ++i) { hA[i] = 1.f; hB[i] = 2.f; }

    float *dA, *dB, *dC;
    CUDA_CHECK(cudaMalloc(&dA, bytes)); CUDA_CHECK(cudaMalloc(&dB, bytes)); CUDA_CHECK(cudaMalloc(&dC, bytes));
    CUDA_CHECK(cudaMemcpy(dA, hA, bytes, cudaMemcpyHostToDevice));
    CUDA_CHECK(cudaMemcpy(dB, hB, bytes, cudaMemcpyHostToDevice));

    int threads = 256;
    int blocks = (n + threads - 1) / threads;
    vecAdd<<<blocks, threads>>>(dA, dB, dC, n);
    CUDA_CHECK(cudaGetLastError());
    CUDA_CHECK(cudaDeviceSynchronize());

    CUDA_CHECK(cudaMemcpy(hC, dC, bytes, cudaMemcpyDeviceToHost));
    for (int i=0; i<n; ++i) if (hC[i] != 3.f) return 2;
    printf("C[0]=%f, all %d checked\n", hC[0], n); // 应全部为 3

    CUDA_CHECK(cudaFree(dA)); CUDA_CHECK(cudaFree(dB)); CUDA_CHECK(cudaFree(dC));
    delete[] hA; delete[] hB; delete[] hC;
    return 0;
}
\end{tcode}

要点：
\begin{itemize}
    \item 设备端函数用 \texttt{\_\_global\_\_} 修饰，由 Host 启动；
    \item 必须用 \texttt{if (i < n)} 防止越界（末尾 Block 可能超出）；
    \item \texttt{cudaMemcpy} 最后一参指明方向：\texttt{HostToDevice} / \texttt{DeviceToHost} / \texttt{DeviceToDevice}。
\end{itemize}

编译示例：
\begin{tbash}
nvcc -O2 vec_add.cu -o vec_add
./vec_add
\end{tbash}

\end{example}

\begin{exercise}
将 n 改为 257、线程数保持 256，计算块数和多余线程数，再运行程序确认没有越界。
\end{exercise}
\paragraph*{内存层次（入门）}

\begin{itemize}
    \item \textbf{Global memory}：容量大、延迟高，\texttt{cudaMalloc} 得到的指针通常指向此处；
    \item \textbf{Shared memory}：Block 内共享的片上暂存，延迟低、容量小，适合复用数据；
    \item \textbf{Registers / Local}：每线程私有；寄存器溢出时可能落到 local memory。
\end{itemize}

Shared memory 示例骨架：
\begin{tcode}
__global__ void demo(float* out, const float* in, int n) {
    __shared__ float tile[256];
    int tid = threadIdx.x;
    int i = blockIdx.x * blockDim.x + tid;
    tile[tid] = (i < n) ? in[i] : 0.f;
    __syncthreads(); // 等待块内全部写完再读
    if (i < n) out[i] = tile[tid]; // 示意：实际可做归约、卷积滑窗等
}
\end{tcode}
上述骨架要求每块恰好 256 个线程，不能让部分线程提前返回后再执行块内屏障。块内协作读写前务必 \texttt{\_\_syncthreads()}，否则存在数据竞争。

\paragraph*{错误检查习惯}

生产代码应对每次 CUDA API 检查返回值，例如：
\begin{tcode}
#define CUDA_CHECK(call) do { \
  cudaError_t e = (call); \
  if (e != cudaSuccess) { \
    fprintf(stderr, "CUDA error %s:%d: %s\n", __FILE__, __LINE__, \
            cudaGetErrorString(e)); \
    exit(1); \
  } \
} while(0)
\end{tcode}
Kernel 启动为异步，常用 \texttt{cudaGetLastError()} 与 \texttt{cudaDeviceSynchronize()} 捕获启动/执行错误。

\paragraph*{与 CMake 集成}

现代 CMake（3.18+）推荐启用 CUDA 语言并链接 Toolkit 目标：
\begin{tcode}
cmake_minimum_required(VERSION 3.18)
project(cuda_demo LANGUAGES CXX CUDA)
find_package(CUDAToolkit REQUIRED)
add_executable(vec_add vec_add.cu)
target_link_libraries(vec_add PRIVATE CUDA::cudart)
\end{tcode}

\begin{conclusion}
\begin{itemize}
\item Thread 执行代码，Block 内线程协作，Grid 包含所有 Block。
\item 索引必须检查边界；网格向上取整后，多余线程不应访问数组。
\item 共享内存只在块内共享；屏障要求块内线程正确参与。
\item 先检查启动错误，再检查同步错误；性能计时也必须考虑异步执行。
\end{itemize}
\end{conclusion}

\subsubsection{从算子到推理部署*}

手写 kernel 适合学习与关键热点优化；多数视觉推理优先走成熟栈：
\begin{enumerate}
    \item 训练框架导出 \textbf{ONNX}（跨框架中间表示）；
    \item 用 \textbf{TensorRT}（或 OpenVINO 等）构建优化引擎（融合算子、精度校准等）；
    \item 在线加载 \texttt{.engine} 做低延迟推理。
\end{enumerate}
TensorRT 依赖 CUDA；引擎往往与具体 GPU 架构相关，换卡常需重建。
深度学习章中的部署小节与此衔接：本卷强调 CUDA 是 GPU 路径的底座，
具体 TensorRT API 可在项目仓库与 NVIDIA 文档中深入。

\begin{example}
某流水线上传 2 ms、计算 1 ms、下载 2 ms，总延迟为 5 ms。把 kernel 优化为 0.5 ms 后总延迟为 4.5 ms，只减少 10\%；仅报告算子“快一倍”会掩盖整体瓶颈。
\end{example}

\begin{exercise}
若连续三个算子共需 3 ms，比较每个算子各自上传下载与统一上传下载一次的总用时。假定每次传输仍为 2 ms。
\end{exercise}

\subsubsection{常见问题与边界}

\begin{itemize}
    \item 笔记本双显卡：确认进程跑在 NVIDIA 独显上（\texttt{nvidia-smi} 看进程）。
    \item WSL / 容器：需额外配置 GPU 透传，与裸机步骤不同。
    \item 无 GPU 环境：可学概念与写可在 CPU 回退的代码路径；本章验收中的运行项需有可用设备。
\end{itemize}
