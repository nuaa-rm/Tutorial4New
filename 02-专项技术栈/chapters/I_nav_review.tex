\section{本章小结}
\begin{conclusion}
这一章我们从“想让哨兵去某个地方”走到了一个可以保存日志的导航软件闭环。首先把坐标接对，再确认地图和代价地图表达的是哪里；规划器根据代价找路，控制器结合附近环境算速度，最后由执行接口让车移动。某一段断了，就沿对应输入输出去查，不用把所有参数一起调一遍。

你应能独立查询 TF、换算格心、说明滤波误删的条件、运行最短路与恢复序列，并在 Jazzy 中核对实际插件和 action 结果。SLAM 的完整前后端、车体模型和实车建图还要继续深入；本章用明确的合成地图和软件模型把接口跑通，卷三再处理赛场、传感器和底盘的真实条件。
\end{conclusion}

\begin{problemset}
\item\label{prob:nav-chain} 基础：已经有全局路径，却没有速度输出。按输入、状态和输出各说一个具体检查点，为什么换一个全局规划器未必有用？
\item\label{prob:nav-frames} 基础：map、odom、base\_link 的职责是什么？已知 $T_{map,base}$ 和 $T_{odom,base}$，怎样计算 $T_{map,odom}$，哪个变换应保持局部连续？
\item\label{prob:nav-cell} 基础：分辨率 0.1 m/cell、原点 (1,2)、偏航为零，索引 (2,3) 的格心在哪里？图片有 40 行，第 0 行对应地图哪个 j？
\item\label{prob:nav-filter} 基础：VoxelGrid 的输出为何不是体素中心？如果稀疏真实障碍被 SOR 删除，应该核对哪些假设？为什么“平的都是地板”不能直接用？
\item\label{prob:nav-layers} 基础：静态层、障碍层和膨胀层分别做什么？OccupancyGrid 的 100 和原始代价地图的 254 能直接按同一个编码解释吗？
\item\label{prob:nav-dijkstra} 基础：A→B 代价 2、B→C 代价 2、A→C 代价 5，Dijkstra 选哪条路？四邻接单位边权的 A* 可用什么启发式？
\item\label{prob:nav-running} 基础：Fallback 第一个子项 Running 时会立刻执行第二项吗？恢复成功一次是否等同导航最终成功？
\item\label{prob:nav-braking} 提高：v=2 m/s、可用减速度 1 m/s$^2$、总延迟 0.2 s，不含额外余量的停车距离是多少？4 m 方形窗口正中心的车有足够前向长度吗？
\item\label{prob:nav-runtime} 实践：运行本章 Nav2 闭环与障碍内目标请求，分别保存结果与日志。指出失败发生在规划还是跟踪，解释为何前一次成功不能证明任意目标都可达。
\item\label{prob:nav-recovery} 实践：实际运行成功、持续失败与等待不结束三条恢复序列，提交逐 tick 的返回值与节点日志。把重试上限改为 0 再验证，指出最终失败或超时出口。
\end{problemset}

\section{本章验收}
\begin{enumerate}
\item 从本章目录实际生成地图、构建 PCL 示例，向检查者展示质心、过滤前后数量、图片与 YAML 的对应；给定新原点与索引时能算出并运行核对格心。
\item 实际启动 Jazzy 的 Nav2 规划/控制与软件模型，展示 map、代价地图、插件、TF、cmd\_vel 和 action 的输入输出。提交同一次结果数组、日志与图，检查轨迹和车体半径相对障碍的余量；运行障碍内目标，沿失败日志定位中断位置。
\item 在独立演示树中实际查询变换，并演示缺失坐标系的异常。说明真实定位修正与软件中固定 map→odom 的区别，不覆盖其他项目的变换。
\item 按检查者给定序列运行行为树等价模拟器，展示清理和等待两种恢复分支、Running 的传播、有限重试与超时出口。该模拟器验证任务语义，实车清图、旋转、后退与动态避障在卷三继续验收。
\end{enumerate}
