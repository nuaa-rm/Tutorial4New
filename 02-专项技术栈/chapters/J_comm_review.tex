\section{本章小结}
通信先约定角色、边界和资源所有者，再讨论吞吐量。TCP 需要自定义帧边界，串口需要校验和重同步；状态数据可覆盖旧值，事件则需独立的可靠投递策略。应熟练用假数据验证半包、粘包、坏帧与过期数据，真实协议参数按接口文档查。

\begin{problemset}
\item 基础：一个设备字节流能否由两个互不协调的进程同时解析？建议如何组织？
\item 基础：TCP 服务端执行 bind、listen 后，客户端应执行哪一步建立连接？
\item 基础：教学长度前缀流依次到达 02、41、42，应输出多少帧、什么内容？
\item 基础：CRC 失败后为什么不能直接把载荷交给融合层？CRC 能否验证发送者身份？
\item 基础：外部速度为 3000 mm/s，桥接到使用 m/s 的 ROS 消息应填多少？
\item 提高：旧连接的异步清理回调在新连接建立后才到达，应该如何保护新连接？
\item 实践：用字典槽连续写入同一状态的 100、200、300 三个值，然后消费一次。结果为何？若改为三次必须执行的事件应如何处理？
\end{problemset}

\section{本章验收}
\begin{enumerate}
    \item 现场运行本机 TCP echo，按检查者要求断开、重连，展示旧连接不会关闭新连接的日志。
    \item 向教学帧解析器注入噪声、分片与坏 CRC，展示恢复后的有效帧；用故障清单解释与串口解析的对应关系。
    \item 在两条模拟链路中暂停一条，展示另一条仍推进；记录队列长度、代次和过期丢弃计数。
\end{enumerate}
