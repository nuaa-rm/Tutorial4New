\section{本章小结}
走到这里，我们已经把卷一里独立运行的 C++ 程序，连成了可以互相传消息的小系统。你发出一条消息，另一个节点就能接住并处理它；换成自定义接口，还能把几项相关的数据一起交给下一环。回头看，节点让我们分清各部分做什么，话题和服务把它们连接起来，功能包则把代码、接口和依赖组织好。发布、订阅、定时器和自定义接口这几件事，值得你再独立做一遍，直到能从空工作空间把收发流程跑通。

消息跑通后，我们还用 rqt、RViz2 和 Foxglove 把它们画了出来：曲线帮助看变化，图像与标注帮助核对同一帧，三维场景帮助检查坐标和尺寸，录制回放则让我们能停下来找问题。接着，我们把“这次能运行”变成了“下次也知道怎样启动”：声明依赖，构建并安装，加载环境，再用 Launch 保存节点、参数和命名空间的安排，最后通过话题和日志检查结果。如果改了代码却还是旧输出，先看看启动的究竟是哪份程序；如果节点之间收不到消息，再沿着通信域、发现范围、接口与 QoS 查下去。CLion 也要核对它与终端使用的环境和程序路径，这些线索能帮你一步步缩小范围。

换成大图像以后，我们又遇到了新的问题：每隔 4 ms 来一帧，怎样及时交给识别节点？这一部分，我们先算像素负载，再检查进程边界、消息所有权和借出条件，最后用相同输入做对照。组件的进程内通信可以交接消息所有权；跨进程时，Fast DDS Data Sharing 和 Cyclone DDS iceoryx 可以在满足条件时共享原始样本，Zenoh SHM 传递的则是序列化数据。标准 Image 的变长字段不能直接走原始样本借出这条路，换成定长图像后，还要检查实现与配置是否支持。

读实验结果时，记得把发送频率、接收比例和延迟放在一起看。接收端只拿到少量帧时，漂亮的延迟数字还不足以说明链路合适；接上真实相机后，也要继续检查采集、转换、识别和观测支路，看看时间花在哪里、处理的画面有多旧。具体配置和接口名字可以用时回来查，先把“提出问题、算清预算、固定条件做对照、根据结果选方案”的过程练熟。

接下来先用习题和验收看看自己还有哪里不顺，再往后走。下一章我们会把通信问题扩展到多台机器，继续处理数据怎样传过去、怎样确认收到，以及连接出了问题该怎样恢复。有了这一章的收发和排障经验，我们就可以带着这些问题继续动手了。

\begin{problemset}
\renewcommand{\theenumi}{\arabic{enumi}}
\item \label{prob:v2-ros-1}基础：一个包里有两个可执行程序，每个程序创建一个节点。包、进程、节点分别有几个？同一进程能否有多个节点？
\item \label{prob:v2-ros-2}基础：colcon build 后出现 build、install、log。运行前应加载哪个目录中的环境脚本？
\item \label{prob:v2-ros-3}基础：create\_publisher 的整数参数 10 是否表示“每秒发送十次”？哪个机制决定周期发布？
\item \label{prob:v2-ros-4}基础：包名 my\_msgs 与消息文件 My.msg 编译后，C++ 消息类型如何书写？
\item \label{prob:v2-ros-5}提高：发布者和订阅者使用相同话题名，仍收不到数据，按什么顺序排查？
\item \label{prob:v2-ros-6}实践：启动 demo\_nodes\_cpp 的服务端，调用 AddTwoInts，请求 a=-4、b=9，记录响应。
\item \label{prob:v2-ros-7}基础：修改所在发行版的本机发现范围设置后，为什么旧节点可能继续跨机器通信？它与 \nolinkurl{ROS_DOMAIN_ID} 是否能替代认证？
\item \label{prob:v2-ros-8}提高：Launch 中 namespace 为 blue、相对话题 status 重映射为 health，完整话题名是什么？源目录有 YAML，但启动时报文件不存在，应检查什么？
\item \label{prob:v2-ros-9}提高：定时器每 200 毫秒发布消息，INFO 日志按 2000 毫秒限流。两者频率分别是多少？FATAL 是否自动结束程序？
\item \label{prob:v2-ros-10}实践：同一包在 CLion 中运行的是新代码，ros2 run 却仍显示旧文本。说明构建、安装和环境三个环节的排查顺序，并给出修复命令。
\item \label{prob:v2-ros-11}基础：1440×1080@250 Hz 的 Bayer8 转成 BGR8 后，纯像素负载率变为多少？每多复制一次 BGR8，估算新增读写量。为什么队列加深不能补足一个长期 8 ms 的串行阶段？
\item \label{prob:v2-ros-12}提高：两个节点在同一个 Distrobox 中，分别运行在两个组件容器进程里。能否使用本章的进程内直接交接？若合并进程，还需要什么条件，又会改变什么故障边界？
\item \label{prob:v2-ros-13}提高：loan\_probe 的 FixedImage 能力返回 true，Image 返回 false，但程序运行成功。分别能得到什么结论？还缺哪些证据才能证明完整的跨进程图像零拷贝？
\item \label{prob:v2-ros-14}实践：某轮 RMW 对照发送接近 250 Hz，接收比例只有 40\%，P95 为 2 ms；另一轮接收比例为 99\%，P95 为 4 ms。说明为什么不能单按 P95 选型，并设计下一轮相机链路测量。
\item \label{prob:v2-ros-15}提高：Marker 持续发布却不可见、检测框开启时间同步后画面停住，分别应该检查哪些字段与显示设置？为什么只从 MarkerArray 中移除对象不能保证删除？
\item \label{prob:v2-ros-16}基础：写出 Foxglove 中把 /viz/pose 的四元数 yaw 画成角度、把 /viz/twist 的线速度画成模长的路径。测量时间曲线与 XY 轨迹时，两轴差值和直线距离各有什么单位？
\end{problemset}

\section{本章验收}
首次学习先完成前 5 项；后 3 项随进阶部分补验。完整学习后仍需完成全部 8 项，不用一次把两阶段都挤在一起。
\begin{enumerate}
    \item 从空目录创建独立工作空间，现场运行字符串发布与订阅；由检查者更改输入文本，展示对应输出。
    \item 在完整工程中增加一个自定义字段并重新构建，展示接口查询、带时间戳的消息和定时器频率。
    \item 使用 rqt 展示数据流、数值曲线与图像；用 RViz2 展示 TF、轨迹和 Marker 的删除恢复。用 Foxglove 保存 Plot、Image、3D 布局，展示四元数转角度、图像时间同步与一次两点测量，再录制并回放 MCAP；说明停止发布后的显示差异并提交启动命令、布局和记录。账号权限不足时记录 Foxglove 待补项，由检查者在可用账号下补验。
    \item 提交包含清单、构建规则、参数与 Launch 的 training\_tools 包；由检查者指定命名空间和文本，现场启动并展示对应话题。
    \item 现场演示本机通信范围设置与恢复，保存一份独立实验日志；在 IDE 中命中发布回调断点，并说明实际运行的程序路径。
    \item 现场构建 image\_path\_demo，由检查者指定尺寸、RMW 和组件布局；选择 Zenoh 时演示自己的路由器启动与正常关闭；展示原始日志、接收比例与延迟记录，说明计时点和合成图像的验证范围。
    \item 现场切换借出探测配置，展示定长类型、Image 与禁用后的结果。再对三种中间件统一运行普通与定长图像的像素检查和性能对照，展示两端借出能力，说明类型布局、共享方式、工具兼容性和样本使用期限。
    \item 使用实际相机逐步升到可用的目标帧率，记录采集、回调、识别完成与输出时刻；说明主链路与降频观测支路的布局。设备达不到指定参数时记录实际尺寸、格式与频率，不以合成实验代替物理采集验收。
\end{enumerate}
