\subsubsection{软件无线电在做什么}
上一章我们已经知道怎样把字节接起来。不过无线电设备交给你的，往往还不是坐标帧，而是一长串看起来没什么规律的复数。这时候先别急着接 TCP：我们得把这些样本还原成比特，再检查它们到底能不能作为一条消息使用。

\textbf{软件定义无线电（SDR，Software Defined Radio）}把混频、滤波、解调等处理尽可能放到数字域，用软件完成。天线、射频前端和模数转换器（ADC，Analog-to-Digital Converter）仍负责把真实信号采进来；软件再做同步、解调和组帧。你可以重放同一段录包、换算法比较结果，但采样前就被滤掉或因饱和而损坏的信息，并不会因为换了 Python 代码就自己长回来。

雷达方向采用无线电信息链路时，会把解出的坐标等字段交给地面视觉，再按当年的接口上报。这里的“雷达方向”是高台感知站的方向名，不是说这块 SDR 就是导航用的激光雷达（LiDAR）。本章用合成波形把接收链跑通，真实赛场波形和频点继续查队内保存的当年文档，不能拿教学帧直接上场。

如果拿到的是 IQ 录包，就从数字处理开始；如果已经拿到通过校验的坐标字段，就从单位、时间和融合接口开始。图~\ref{fig:v2-sdr-chain} 把两者分开，后面的离线项目覆盖图中数字接收部分，Pluto 接收例子只覆盖前面的采样接口。
\end{example}

\subsubsection{从 IQ 开始：复数并不是多余的一半}
IQ 中的 I 是同相分量（In-phase），Q 是正交分量（Quadrature），我们把它们写成 $x[n]=I[n]+jQ[n]$。你可以把它想成复平面上的一个箭头：长度是幅值，方向是相位。只有长度的照片，分不清箭头是在顺时针还是逆时针转；保留 I 和 Q 才能观察这个区别。

对于频率 $f$、采样率 $f_s$ 的理想复数单音，样本是 $x[n]=e^{j2\pi fn/f_s}$。采样率说的是每秒几个\emph{复数样本}，不是把 I、Q 分别数一次后再翻倍。离散时间中的频率会按 $f_s$ 周期重复；常用的基带频率表示区间是 $[-f_s/2,f_s/2)$。因此提高采样率、调整模拟滤波与本振要一起考虑，不能只靠软件区分已混叠的两个信号。
\begin{example}[转一个方向，再转回来]
本章的完整工程位于本卷 \path{examples/sdr/iq-replay-demo}。离线部分只依赖 Python 3.10 以上与 NumPy；Ubuntu 24.04 可以先安装 \texttt{python3-numpy}。进入这个目录后运行下面的 tone\_demo.py。
\begin{sdrblock}
\lstinputlisting[language=Python,frame=single,numbers=left,caption={tone\_demo.py：相位、频率与混叠}]{examples/sdr/iq-replay-demo/tone_demo.py}
\end{sdrblock}
\texttt{np.arange(count)} 生成样本下标，复指数生成样本；后一个样本乘前一个的共轭，再取 angle，得到相邻相位差。运行 \texttt{python3 tone\_demo.py}，正负 1000 Hz 分别输出约 $\pm0.785398$ rad，幅值都是 1。9000 Hz 的样本与 1000 Hz 相同，因为两者正好差一个采样率。这里 angle 给主值，不能靠这一句恢复超出表示区间的原始频率。
\end{example}

\end{exercise}

\subsubsection{先把录包做成可以回放的小工程}
接下来我们用二进制相移键控（BPSK，Binary Phase Shift Keying）：比特 0 映射到 $+1$，比特 1 映射到 $-1$。一个符号保持 8 个样本，采样率 8000 Hz，所以符号率为 1000 符号/秒。这里一个符号携带一个比特；换成别的调制方式，三种速率就不能这样直接等同了。

项目分成下面几个文件。先有字段，再有比特和波形；接收时走反方向，录包文件让两次运行真正分开。
\begin{sdrblock}
\begin{lstlisting}[language={}]
iq-replay-demo/
  README.md
  frame.py          # 教学帧与比特、CRC、字段
  synth.py          # BPSK、频偏、相位、噪声
  record.py         # 保存与检查录包
  decode.py         # 同步、符号判决、组帧

\end{lstlisting}
\end{sdrblock}

命令入口在 replay.py。\texttt{generate folder} 合成并保存，\texttt{decode folder} 则从文件载入，不能拿生成时还留在内存中的数组假装做了回放。
\begin{sdrblock}
\lstinputlisting[language=Python,frame=single,numbers=left,basicstyle=\footnotesize\ttfamily,caption={replay.py：生成与回放入口}]{examples/sdr/iq-replay-demo/replay.py}

先在项目目录执行 \texttt{python3 replay.py generate /tmp/sdr-good}，应显示已保存 670 个复数样本，目录里有 \texttt{iq.npy} 与 \texttt{metadata.json}。Distrobox 用户先进入 ubuntu2404；离线程序不用加载 ROS。通用形式为 \texttt{python3 replay.py generate folder [选项]}，folder 换成自己的录包目录；\texttt{--x-mm} 是毫米值，\texttt{--phase} 是弧度，\texttt{--offset-hz} 是已知频偏，\texttt{--noise} 控制噪声标准差。只有 generate 使用这些选项，decode 使用保存的元数据。

\end{note}

\begin{conclusion}
IQ 是样本，符号是调制单位，比特组合成帧，字段才有坐标等业务含义。同步解决起点与参考，解调和判决恢复比特，CRC 检查帧的一致性，三者不能互相替代。本例已知频偏和符号率，采用矩形脉冲、整样本偏移、单帧和轻噪声；实际波形还要处理频偏估计、采样时钟误差、多径、连续流与滤波，不能把本例的相关峰当作所有接收问题的答案。
\end{conclusion}

\subsubsection{分阶段切换：状态机不会替你重新调谐}
接收流水线说的是“一帧怎样解出来”，阶段状态机说的是“现在该用哪套配置”。它们回答的不是同一个问题。教学中可以按一级、二级、信息阶段推进，同一块单通道设备一次使用一个 profile（配置组）。这些阶段名只是演示，是否有这样的赛制，要查当年的规则。
\begin{example}[先检查阶段与事件是否对得上]
state\_demo.py 前半部分给出模拟采样率和带宽。收到匹配事件才推进，timeout 留在原阶段；reset 即使已经在初始状态，也增加代次，表示旧任务与新任务已经分开。
\begin{sdrblock}
\lstinputlisting[language=Python,frame=single,numbers=left,lastline=24,caption={state\_demo.py：阶段与配置组}]{examples/sdr/iq-replay-demo/state_demo.py}
\end{sdrblock}
下面的源选择和入口一起覆盖两项能力：阶段切换、统一时钟下的新鲜度，后一个紧接着讲。运行 \texttt{python3 state\_demo.py}，前五行阶段依次是 level1、level2、level2、information、level1，代次依次为 0、1、1、2、3。
\begin{sdrblock}

\subsubsection{与地面视觉衔接：校验通过还得看时间}
坐标终于解出来了，接下来才到上一章的单位换算和转发。这里只用同一个逻辑时钟检查年龄：无线电数据足够新鲜就优先用，过期后再看视觉；两路都过期就返回 None，而不是让一个旧坐标永远占着位置。这个简化优先级用于演示，实战还需要置信度、坐标系和同步约定。
\begin{example}[让旧无线电坐标先退场]
刚才 state\_demo.py 中 radio 的时间是 9.7 s，vision 是 9.9 s；当前 10.0 s，有效期 0.2 s，程序应选择 vision。到 11.0 s，两者都过期，输出 None。select\_source 同时要求年龄大于等于 0，未来时间戳也不能直接当成“特别新鲜”。
\end{example}
\begin{note}
这些坐标都是米；实机还要写清坐标原点、轴向、数据产生时间、序号和接收时间。录包回放发生在今天，不等于样本就是今天采的。不同机器的墙钟若没有同步，不能直接相减；可按接口约定用本机单调接收时钟检查\emph{接收后年龄}，但它不能替代采集时刻。
\end{note}
\begin{exercise}\label{ex:v2-sdr-fresh}
将 radio 时间改为 10.1 s，确认当前 10.0 s 不会选择它；再让 vision 也过期，核对 None。解释两路数据同时消失时应该给上层什么状态，而不是继续沿用最后坐标。
\end{exercise}
\begin{conclusion}
阶段状态机选择接收配置，解码流水线恢复有效字段，融合策略再看单位、坐标系和年龄。切换配置要隔离旧代次；切换数据源要确认备用源足够新鲜。收到一帧、通过 CRC、能用于当前融合，是三次不同的判断。
\end{conclusion}

\subsubsection{接上 Pluto：先只检查接收接口*}
如果你暂时没有设备，离线部分可以先练熟。常见教学板 ADALM-PLUTO 基于 AD936x 射频收发器，主机侧用 libiio（Industrial I/O）和 Python 封装 pyadi-iio 配置并读取缓冲。ROS 环境不是它们的前提；但在 Distrobox 中运行时，USB、设备网络和驱动必须在容器里也可达。
\begin{note}
先由实验负责人确认设备、天线、接线和接收频点，再操作设备。本例只调用接收，没有发射；若另做发射实验，必须先核对当地频谱法规、赛场规则与场地许可，不能因为网上例子的功率很小就直接照抄。
\end{note}
\begin{example}[把安装和设备可达分开检查]
在 Ubuntu 24.04 容器的项目目录执行以下安装。虚拟环境沿用系统 NumPy，Python 包安装进 .venv；不要用 sudo pip 改系统 Python。这里的版本组合已检查导入，换版本时再查 ADI 文档。
\begin{sdrblock}
\begin{tbash}
sudo apt install libiio0 libiio-utils libad9361-0 python3-venv
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install pyadi-iio==0.0.21 pylibiio==0.25
.venv/bin/python -c 'import adi, iio; print(adi.__version__, iio.version)'
iio_info --help
iio_info -S usb
\end{tbash}
\end{sdrblock}
导入应显示 pyadi-iio 0.0.21 与 libiio 0.25。按本机帮助，-S usb 仅扫描 USB；旧文档里的 -s 写法要以实际版本为准。若显示 \texttt{No IIO context found}，只是当前没发现设备；先查容器是否看见 USB，再查驱动和设备地址。全部后端扫描若出现 Avahi/DNS-SD 错误，是网络发现条件不齐，别先去重装 Python。已有明确 IP 时可用 \texttt{iio\_info -u ip:设备地址} 定向检查。

实际接收入口如下。\texttt{sample\_rate} 是复数采样率，\texttt{rx\_lo} 是接收本振，\texttt{rx\_rf\_bandwidth} 是射频接收滤波带宽；这三个参数不能当成一个“频率”随便换。gain 使用 slow\_attack 自动增益，buffer\_size 是本次缓冲样本数；最后销毁 RX 缓冲，避免把读取资源一直留着。

\lstinputlisting[language=Python,frame=single,numbers=left,basicstyle=\footnotesize\ttfamily,caption={capture\_pluto.py：配置、接收、录存与清理}]{examples/sdr/iq-replay-demo/capture_pluto.py}
\end{sdrblock}
先执行 \texttt{.venv/bin/python capture\_pluto.py --help}。实机调用形式为 \texttt{capture\_pluto.py --uri URI --lo-hz HZ folder}，用自己的 URI、批准的接收中心频率和新目录替换；不要把未知频点当默认值。成功时应显示 4096 个样本、实际类型和本振读回，并产生两个录包文件。这里尚未接上实机核验，设备异常不能被空结果冒充成功。

真实录包没有我们事先约定的前导和符号率，不能直接塞给教学 decode。接收端的调用也不保证持续无丢样；实际调谐稳定、USB 吞吐、增益、模拟饱和和断开恢复，都要在设备上单独检查。保存短样时附配置、设备与采集时间，不提交未经批准的真实频点、隐私信息或大体积录包。
\end{example}
