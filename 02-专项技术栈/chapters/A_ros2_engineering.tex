\subsubsection{先检查环境，再检查代码}
\label{sec:ros2-environment}

本节统一使用 Ubuntu 22.04、ROS2 Humble 和 Bash。终端能运行节点、IDE 却找不到包，通常应先检查两者继承的环境。系统安装是底层工作空间（underlay），自己的安装目录是覆盖工作空间（overlay）；先加载底层，再加载覆盖层。同名包可能被覆盖，因此不要在同一终端随意叠加多个项目。

\begin{center}
\begin{tabular}{p{0.40\textwidth}p{0.52\textwidth}}
\toprule[1.5pt]
变量 & 作用 \\
\midrule[1pt]
\nolinkurl{ROS_VERSION / ROS_DISTRO} & 判断当前终端所加载的 ROS 版本线索。\\
\texttt{AMENT\_PREFIX\_PATH} & ament 查找已安装包的前缀。\\
\texttt{CMAKE\_PREFIX\_PATH} & CMake 查找依赖的前缀。\\
\nolinkurl{PYTHONPATH / LD_LIBRARY_PATH} & Python 模块与动态库搜索路径。\\
\texttt{ROS\_DOMAIN\_ID} & 通信域编号；通信双方需要一致。\\
\texttt{ROS\_LOCALHOST\_ONLY} & Humble 中设为 1，将 ROS 通信限制在本机。\\
\texttt{RMW\_IMPLEMENTATION} & 选择已经安装的中间件实现。\\
\bottomrule[1.5pt]
\end{tabular}
\end{center}

通常让环境脚本维护搜索路径，不逐项手工拼接。ROS1 的 \texttt{ROS\_PACKAGE\_PATH} 不是修复 ROS2 包查找问题的通用办法。变量值正确也不代表包已经构建并安装，仍要查询包的位置。

\begin{example}[确认终端实际使用的包]
完成前面的工作空间练习后，在新终端执行：
\begin{tbash}
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
printenv ROS_VERSION ROS_DISTRO AMENT_PREFIX_PATH
ros2 pkg prefix my_package
ros2 pkg executables my_package
\end{tbash}
应显示 ROS 版本 2、发行版 humble，以及自己工作空间中的包安装前缀。若路径指向别的工作空间，先修正加载顺序；若找不到包，检查构建是否成功、包名是否一致。
\end{example}

\paragraph*{在实验室中只与自己的节点通信}
域编号用于把实验分组；它不是密码。同一个域也不保证必然通信，还要检查发现范围、接口类型、QoS 与网络。Linux 教学环境可从 0--101 中协调分配编号；实际可用范围还受操作系统端口范围和进程数量影响。

\begin{example}[临时启用本机通信并恢复]
在两个终端分别执行以下四行，然后分别运行最后两条命令中的一条：
\begin{tbash}
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=42
export ROS_LOCALHOST_ONLY=1
ros2 daemon stop
# 终端 A
ros2 run demo_nodes_cpp talker
# 终端 B
ros2 run demo_nodes_cpp listener
\end{tbash}
应看到本机 listener 收到消息。在另一台机器使用相同域和普通网络发现时，不应收到本次本机发布的数据。测试前关闭遗留示例节点，避免把别的发布者当成结果。

按 Ctrl+C 停止两个节点。在两个终端分别执行下列命令，再重新启动节点，恢复默认域和普通发现范围：
\begin{tbash}
unset ROS_LOCALHOST_ONLY ROS_DOMAIN_ID
ros2 daemon stop
\end{tbash}
若启动脚本或上层服务也设置了这些变量，需要同步检查。已有进程不会因另一终端执行 unset 而改变配置。
\end{example}

长期设置可先用 \nolinkurl{cp -p ~/.bashrc ~/.bashrc.ros-backup} 备份，再编辑 \nolinkurl{~/.bashrc}，保留唯一生效的 \texttt{export ROS\_LOCALHOST\_ONLY=1}。已有备份时另取名称，避免覆盖。恢复时删除该行，并在当前终端 unset 或启动新终端；重新加载一个不含该变量的文件，并不会清除当前进程已存在的变量。原资料的脚本用途是修改终端启动配置，执行脚本本身也不能改变父终端环境。

\begin{note}
ROS2 不使用 ROS1 的 Master、\texttt{roscore} 或 11311 端口来组织通信。限制本机发现不是防火墙，也不提供身份认证，不会禁止程序自行建立的其他网络连接。需要跨机器时，先恢复通信范围，再排查网络；容器的网络命名空间也要单独确认。
\end{note}

\paragraph*{切换中间件与进阶变量}
切换 RMW 前先安装对应实现，然后停止旧节点和 CLI 后台守护进程（daemon），在通信两端一致配置后重启。不要只改变量，却让旧进程继续运行。

\begin{example}[切换至 Cyclone DDS]
在目标 Ubuntu 教学机安装软件后，在两个新终端中分别加载并设置：
\begin{tbash}
sudo apt install ros-humble-rmw-cyclonedds-cpp
source /opt/ros/humble/setup.bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
ros2 daemon stop
# 在一个终端运行 talker，另一个运行 listener
ros2 run demo_nodes_cpp talker
\end{tbash}
另一个终端的最后一条改为 \nolinkurl{ros2 run demo_nodes_cpp listener}。完成后停止节点、unset 该变量并停止 daemon，可恢复环境的默认选择。
\end{example}

\texttt{CYCLONEDDS\_URI} 与 \nolinkurl{FASTRTPS_DEFAULT_PROFILES_FILE} 分别用于对应 DDS 实现的配置；不要把一家的 XML 给另一家。\texttt{ROS\_DISCOVERY\_SERVER} 用于支持它的 Fast DDS 发现服务器模式，必须先部署服务器，不能仅填写一个 IP 就实现跨网段通信。较新版本中的 \nolinkurl{ROS_AUTOMATIC_DISCOVERY_RANGE} 不作为本章 Humble 的配置步骤。安全部署涉及 SROS2 密钥库及 \texttt{ROS\_SECURITY\_ENABLE}、\texttt{ROS\_SECURITY\_STRATEGY}、\texttt{ROS\_SECURITY\_KEYSTORE}，需配套证书与策略，本章不展开部署。

\begin{conclusion}
\begin{itemize}
\item 找不到包：先确认构建、安装和环境加载，再修改代码。
\item 看不到节点：检查域、发现范围和 RMW，再检查 QoS 与接口。
\item 改了环境：重启相关节点与 daemon；变量只影响继承它的新进程。
\item 域与发现范围负责通信组织；认证和访问控制需要另行配置。
\end{itemize}
\end{conclusion}

让本机 talker 使用域 42、listener 使用域 43，观察现象；把两端统一为 42 后重新启动并验证。写出恢复环境需要处理的进程和变量。
\end{exercise}

\subsubsection{ament、colcon 与可复现的小工程}
\label{sec:ros2-ament}

CMake 描述单个 C++ 包怎样编译和安装；ament 提供 ROS2 的依赖、安装索引和导出约定；colcon 按依赖顺序构建工作空间中的多个包；rosdep 根据依赖键安装系统依赖。\texttt{find\_package} 和 \nolinkurl{ament_auto_find_build_dependencies} 都不会替你下载缺失的软件。

\texttt{package.xml} 是依赖清单，\texttt{CMakeLists.txt} 是构建规则。\texttt{buildtool\_depend} 声明 ament 等构建工具，\texttt{build\_depend} 声明构建依赖，\texttt{build\_export\_depend} 声明下游编译所需依赖，\texttt{exec\_depend} 声明运行依赖，\texttt{test\_depend} 声明测试依赖。\texttt{depend} 合并普通依赖的构建、导出与运行三种用途。只在 cpp 内使用的动态库也可能是运行依赖，不能因此省略运行声明。

\begin{example}[建立共用教学包]
以下文件全部放在 \nolinkurl{~/ros2_ws/src/training_tools}；该包与前面的 \texttt{my\_package} 相互独立。先创建目录：
\begin{tbash}
mkdir -p ~/ros2_ws/src/training_tools/{src,launch,config,test}
cd ~/ros2_ws/src/training_tools
\end{tbash}
保存 \texttt{package.xml}。维护者是教学占位信息，发布自己的包时替换。
\begin{tcode}
<?xml version="1.0"?>
<package format="3">
  <name>training_tools</name>
  <version>0.0.1</version>
  <description>ROS2 engineering exercises</description>
  <maintainer email="student@example.com">Student</maintainer>
  <license>Apache-2.0</license>
  <buildtool_depend>ament_cmake</buildtool_depend>
  <depend>rclcpp</depend>
  <depend>std_msgs</depend>
  <exec_depend>launch</exec_depend>
  <exec_depend>launch_ros</exec_depend>
  <exec_depend>ament_index_python</exec_depend>
  <exec_depend>ros2cli</exec_depend>
  <exec_depend>ros2topic</exec_depend>
  <test_depend>ament_cmake_gtest</test_depend>
  <export><build_type>ament_cmake</build_type></export>
</package>
\end{tcode}
保存 \texttt{src/heartbeat.cpp}。参数在启动时读取一次；改变参数实验时重启节点。
\begin{tcpp}
#include <chrono>
#include <memory>
#include <string>
#include <rclcpp/rclcpp.hpp>
#include <std_msgs/msg/string.hpp>

class Heartbeat : public rclcpp::Node {
public:
  Heartbeat() : Node("heartbeat") {
    const auto text = declare_parameter<std::string>("text", "ready");
    pub_ = create_publisher<std_msgs::msg::String>("status", 10);
    timer_ = create_wall_timer(std::chrono::milliseconds(200),
      [this, text]() {
        std_msgs::msg::String msg;
        msg.data = text;
        pub_->publish(msg);
        RCLCPP_DEBUG(get_logger(), "publish: %s", text.c_str());
        RCLCPP_INFO_ONCE(get_logger(), "first heartbeat");
        RCLCPP_INFO_THROTTLE(get_logger(), *get_clock(), 2000,
                            "heartbeat alive");
      });
  }
private:
  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr pub_;
  rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char ** argv) {
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<Heartbeat>());
  rclcpp::shutdown();
  return 0;
}
\end{tcpp}
保存 \texttt{CMakeLists.txt}。测试文件在后文提供，准备好再开启测试构建。
\begin{tcode}
cmake_minimum_required(VERSION 3.8)
project(training_tools)
find_package(ament_cmake REQUIRED)
find_package(rclcpp REQUIRED)
find_package(std_msgs REQUIRED)
add_executable(heartbeat src/heartbeat.cpp)
target_compile_features(heartbeat PUBLIC cxx_std_17)
ament_target_dependencies(heartbeat rclcpp std_msgs)
install(TARGETS heartbeat DESTINATION lib/${PROJECT_NAME})
install(DIRECTORY launch config DESTINATION share/${PROJECT_NAME})
if(BUILD_TESTING)
  find_package(ament_cmake_gtest REQUIRED)
  ament_add_gtest(test_interval test/test_interval.cpp)
endif()
ament_package()
\end{tcode}
通用构建形式为 \texttt{colcon build [包选择选项] [构建选项]}：
\begin{center}
\begin{tabular}{p{0.42\textwidth}p{0.50\textwidth}}
\toprule[1.5pt]
参数 & 作用 \\
\midrule[1pt]
\texttt{--packages-select 包名} & 仅构建选定包，依赖需已可用。\\
\texttt{--packages-up-to 包名} & 构建目标及工作空间中的递归依赖。\\
\texttt{--symlink-install} & 在可用处采用符号链接安装。\\
\texttt{--cmake-args 参数} & 向 CMake 传递配置参数。\\
\bottomrule[1.5pt]
\end{tabular}
\end{center}
其余选项查询 \texttt{colcon build --help}。下面先关闭测试；rosdep 已按安装章完成初始化后执行依赖安装：
\begin{tbash}
cd ~/ros2_ws
source /opt/ros/humble/setup.bash
rosdep install --from-paths src --ignore-src -r -y
colcon build --packages-select training_tools --cmake-args -DBUILD_TESTING=OFF
source install/setup.bash
ros2 run training_tools heartbeat
\end{tbash}
另一终端加载相同环境后运行 \nolinkurl{ros2 topic echo /status}，应持续收到 ready。消息发布约 5 Hz，日志有自己的输出节奏。
\end{example}

\paragraph*{自动依赖与对外导出}
包变大后可用 \texttt{ament\_cmake\_auto} 减少重复声明。它依据清单寻找依赖，因此清单遗漏不会被自动修复。第三方库的 rosdep 键与 CMake 名称也可能不同，例如通过 \nolinkurl{rosdep resolve opencv2} 查询依赖，而 CMake 通常使用 \nolinkurl{find_package(OpenCV REQUIRED)}。

\begin{example}[同一个包改用 ament 自动宏]
在 \texttt{package.xml} 中把构建工具依赖改为 \texttt{ament\_cmake\_auto}，保留 export 中的 \texttt{ament\_cmake} 构建类型。将整个 CMake 文件替换为：
\begin{tcode}
cmake_minimum_required(VERSION 3.8)
project(training_tools)
find_package(ament_cmake_auto REQUIRED)
ament_auto_find_build_dependencies()
ament_auto_add_executable(heartbeat src/heartbeat.cpp)
target_compile_features(heartbeat PUBLIC cxx_std_17)
if(BUILD_TESTING)
  find_package(ament_cmake_gtest REQUIRED)
  ament_add_gtest(test_interval test/test_interval.cpp)
endif()
ament_auto_package(INSTALL_TO_SHARE launch config)
\end{tcode}
重新执行 rosdep 安装和前例的构建、运行命令，行为应相同。手动版本和自动版本二选一，不把两套安装规则叠加。
\end{example}

若包要供其他包链接，还需安装库和公开头文件。手动构建时，用 \nolinkurl{ament_export_targets} 导出目标，用 \nolinkurl{ament_export_dependencies} 导出依赖；自动宏可简化这些规则。

文件末尾调用 \nolinkurl{ament_package()}，自动版本则调用 \nolinkurl{ament_auto_package()}，完成包索引与配置生成。

组件化还需要代码中的 \nolinkurl{RCLCPP_COMPONENTS_REGISTER_NODE} 和 CMake 的 \nolinkurl{rclcpp_components_register_nodes} 注册；不能靠随意添加 XML 标签注册，也不保证自动实现零拷贝。组件容器与数据所有权优化留作进阶阅读。

\begin{example}[把参数边界变成自动检查]
在 \nolinkurl{test/test_interval.cpp} 保存一个无硬件依赖的边界测试。这里的函数是独立教学逻辑，尚未接入 heartbeat；实际项目应测试生产代码中的同一函数。
\begin{tcpp}
#include <gtest/gtest.h>

bool valid_interval(int milliseconds) {
  return milliseconds >= 10 && milliseconds <= 1000;
}

TEST(Interval, IncludesBounds) {
  EXPECT_TRUE(valid_interval(10));
  EXPECT_TRUE(valid_interval(1000));
}
TEST(Interval, RejectsOutside) {
  EXPECT_FALSE(valid_interval(9));
  EXPECT_FALSE(valid_interval(1001));
}
\end{tcpp}
在工作空间根目录执行：
\begin{tbash}
colcon build --packages-select training_tools --cmake-args -DBUILD_TESTING=ON
colcon test --packages-select training_tools
colcon test-result --verbose
\end{tbash}
两组测试应通过。构建成功不代表测试成功，要查看最后的结果；规范检查可另外接入 ament lint，不应把跳过检查当成默认修复。
\end{example}

\begin{conclusion}
\begin{itemize}
\item 清单声明依赖；rosdep 安装系统依赖；CMake/ament 使用它们构建包。
\item colcon 组织多个包，安装后的索引让 ROS2 能查到可执行程序和资源。
\item 库的导出影响下游使用；只在本包编译成功还不够。
\item 自动宏减少重复配置，不替代依赖声明和测试。
\end{itemize}
\end{conclusion}

\end{exercise}

\subsubsection{用 Launch 保存一次完整启动}
\label{sec:ros2-launch}

启动文件（launch file）把节点、参数、命名空间和话题重映射记录下来，减少多人手工输入的差异。Python 文件提供 \nolinkurl{generate_launch_description()}，返回 \texttt{LaunchDescription}；其中的动作在启动系统中执行。\texttt{Node} 的 package 是包名，executable 是安装后的程序名，name 是节点名，namespace 是命名空间，remappings 改变接口名称，parameters 给节点传参。

\begin{example}[保存并覆盖启动参数]
继续使用 training\_tools。保存 \texttt{config/heartbeat.yaml}：
\begin{tcode}
/**:
  ros__parameters:
    text: "ready from yaml"
\end{tcode}
通配节点键使该参数文件在节点改名或加命名空间后仍适用。保存 \nolinkurl{launch/heartbeat.launch.py}：
\begin{tpython}
from pathlib import Path
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    share = Path(get_package_share_directory('training_tools'))
    return LaunchDescription([
        DeclareLaunchArgument('robot', default_value='robot1'),
        DeclareLaunchArgument('text', default_value='ready from launch'),
        Node(
            package='training_tools', executable='heartbeat',
            name='heartbeat', namespace=LaunchConfiguration('robot'),
            output='screen',
            parameters=[str(share / 'config' / 'heartbeat.yaml'),
                        {'text': ParameterValue(
                            LaunchConfiguration('text'), value_type=str)}],
            remappings=[('status', 'health')],
            additional_env={'RCUTILS_COLORIZED_OUTPUT': '1'},
        ),
    ])
\end{tpython}
后面的参数字典覆盖 YAML 中的同名项。\texttt{LaunchConfiguration} 是运行时求值的替换对象，不是普通 Python 字符串；\texttt{ParameterValue} 明确字符串类型，避免 true 等输入被当成布尔量。

通用形式为 \texttt{ros2 launch 包名 文件名 [参数名:=值]}。安装规则已写在前节 CMake 中，新增资源后重新构建并加载环境：
\begin{tbash}
cd ~/ros2_ws
colcon build --packages-select training_tools
source install/setup.bash
ros2 launch training_tools heartbeat.launch.py robot:=red text:=tracking
\end{tbash}
另一终端加载环境后执行 \nolinkurl{ros2 topic echo /red/health}，应收到 tracking；\nolinkurl{ros2 param get /red/heartbeat text} 应显示同一值。直接运行程序时，可用 \texttt{--ros-args -r \_\_node:=新名 -p text:=内容} 设置名字和参数。
\end{example}

\begin{note}
\nolinkurl{get_package_share_directory} 返回包的安装资源目录，不是源码目录。\texttt{output='screen'} 控制子进程标准输出、标准错误的去向，不等于关闭 ROS 日志文件。\texttt{additional\_env} 在继承的进程环境上增补变量；\texttt{env} 用于指定完整环境，误用可能丢失 PATH 等必要配置。
\end{note}

\paragraph*{组合启动、条件与事件}
\nolinkurl{IncludeLaunchDescription} 复用已有启动文件；\texttt{IfCondition} 和 \texttt{UnlessCondition} 决定动作是否执行；\nolinkurl{SetEnvironmentVariable} 修改所在启动上下文的环境。只影响单个节点时优先用该节点的 \texttt{additional\_env}。

\Needspace{8\baselineskip}
\begin{example}[按需启动观测节点，并在它退出时给出提示]
保存 \texttt{launch/team.launch.py}。本例观测进程来自 ROS2 CLI，启用前确认前文的 \texttt{ros2 topic echo} 可用。
\begin{tpython}
from pathlib import Path
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import (
    DeclareLaunchArgument, ExecuteProcess, IncludeLaunchDescription,
    LogInfo, OpaqueFunction, RegisterEventHandler, SetEnvironmentVariable,
)
from launch.conditions import IfCondition
from launch.event_handlers import OnProcessExit
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration


def report_config(context):
    robot = LaunchConfiguration('robot').perform(context)
    return [LogInfo(msg=f'Observing /{robot}/health')]


def generate_launch_description():
    share = Path(get_package_share_directory('training_tools'))
    observer = ExecuteProcess(
        cmd=['ros2', 'topic', 'echo', '/red/health',
             'std_msgs/msg/String', '--once'],
        output='screen', condition=IfCondition(LaunchConfiguration('watch')),
    )
    return LaunchDescription([
        DeclareLaunchArgument('robot', default_value='red'),
        DeclareLaunchArgument('watch', default_value='true'),
        SetEnvironmentVariable('RCUTILS_COLORIZED_OUTPUT', '1'),
        OpaqueFunction(function=report_config),
        RegisterEventHandler(OnProcessExit(
            target_action=observer,
            on_exit=[LogInfo(msg='Observer exited; heartbeat keeps running.')],
        )),
        IncludeLaunchDescription(
            PythonLaunchDescriptionSource(
                str(share / 'launch' / 'heartbeat.launch.py')),
            launch_arguments={
                'robot': LaunchConfiguration('robot'), 'text': 'team ready',
            }.items(),
        ),
        observer,
    ])
\end{tpython}
本例观测话题固定为 \texttt{/red/health}，所以先保留 robot 默认值；下一道练习将它也改成可配置。重新构建后执行：
\begin{tbash}
ros2 launch training_tools team.launch.py
ros2 launch training_tools team.launch.py watch:=false
\end{tbash}
两条命令分别运行，之间按 Ctrl+C 结束。第一次观测到一条消息后观测进程退出，heartbeat 继续运行；第二次只启动 heartbeat。\texttt{OpaqueFunction} 在执行阶段取得上下文并返回动作，适合必须先把替换对象求值的逻辑；普通传参不必使用它。
\end{example}

\begin{conclusion}
\begin{itemize}
\item 启动参数控制启动文件；节点参数需要再由 parameters 传给节点。
\item 事件处理器先注册，再启动目标动作，避免错过很快退出的进程。
\item 进程启动或退出不是服务就绪信号。依赖服务可用性时，应显式等待服务；需要状态管理时再学习生命周期节点。
\item 组合启动时检查命名空间和重映射后的完整话题名，不能只看源码中的短名。
\end{itemize}
\end{conclusion}
\begin{exercise}
将 team 启动文件的观测话题也与 robot 参数绑定，以 \texttt{robot:=blue} 启动，确认一次性观测能退出。再用 \texttt{watch:=false} 确认只有 heartbeat 运行。
\end{exercise}

\subsubsection{日志：看见故障，也控制输出量}
\label{sec:ros2-logging}

日志记录器（logger）带有名称和严重级别。DEBUG 用于细节，INFO 用于正常阶段事件，WARN 表示异常但仍可继续，ERROR 表示某次操作失败，FATAL 表示严重故障。级别是记录的属性：调用 FATAL 本身不会退出程序，退出和安全处置要由代码明确完成。

\texttt{RCLCPP\_INFO} 等宏使用 printf 风格格式串；\texttt{RCLCPP\_INFO\_STREAM} 使用流表达式；\texttt{\_ONCE} 每个调用点只输出一次，\texttt{\_SKIPFIRST} 跳过首次输出，\texttt{\_THROTTLE} 按指定时钟和毫秒间隔限流，\texttt{\_EXPRESSION} 仅在表达式为真时输出。这些条件只控制日志，不控制回调执行或消息发布。组合宏的准确名称以所用发行版头文件为准。

\begin{example}[区分发布频率、日志级别与限流]
运行前面的 heartbeat：
\begin{tbash}
ros2 run training_tools heartbeat --ros-args --log-level debug
\end{tbash}
应看到每次发布对应的 DEBUG、一次 first heartbeat，以及约每两秒一次 alive。另一终端运行 \texttt{ros2 topic hz /status}，仍约为 5 Hz。停止后改用 \texttt{--log-level warn} 重启，普通日志消失，但话题仍在发布。也可用 \texttt{--log-level heartbeat:=debug} 只设置指定 logger；节点改名后需核对 logger 名。
\end{example}

\paragraph*{控制台、文件与 rosout 是不同出口}
ROS2 默认可把日志发到控制台、后端日志文件和 \texttt{/rosout}。控制台默认使用标准错误流（stderr）；不是低等级走 stdout、高等级走 stderr。Launch 的 screen、log、both 处理子进程输出的路由，与 ROS 自身文件后端应分开理解。

\begin{center}
\begin{tabular}{p{0.45\textwidth}p{0.47\textwidth}}
\toprule[1.5pt]
变量 & 作用 \\
\midrule[1pt]
\texttt{ROS\_LOG\_DIR} & 显式选择日志目录。\\
\texttt{ROS\_HOME} & 未指定日志目录时使用其下的 log；默认基于 \nolinkurl{~/.ros}。\\
\nolinkurl{RCUTILS_CONSOLE_OUTPUT_FORMAT} & 设置控制台格式，例如级别、名称、正文。\\
\nolinkurl{RCUTILS_COLORIZED_OUTPUT} & 1 强制彩色，0 关闭彩色。\\
\nolinkurl{RCUTILS_LOGGING_USE_STDOUT} & 1 改用 stdout，0 使用 stderr。\\
\nolinkurl{RCUTILS_LOGGING_BUFFERED_STREAM} & 0 无缓冲，1 行缓冲。\\
\bottomrule[1.5pt]
\end{tabular}
\end{center}

\begin{example}[为一次实验单独保存日志]
用子 shell 设置变量，退出后不污染当前终端：
\begin{tbash}
(
  export ROS_LOG_DIR="$HOME/ros_logs/heartbeat_test"
  export RCUTILS_CONSOLE_OUTPUT_FORMAT='[{severity}] [{name}] {message}'
  export RCUTILS_LOGGING_BUFFERED_STREAM=0
  ros2 run training_tools heartbeat --ros-args --log-level debug
)
find "$HOME/ros_logs/heartbeat_test" -type f
\end{tbash}
按 Ctrl+C 结束后再执行 find，检查实际生成的文件。重复实验会继续使用这个目录，需要按实验编号另取目录名。控制台格式还可使用 \texttt{\{time\}}、\texttt{\{file\_name\}}、\texttt{\{function\_name\}} 和 \texttt{\{line\_number\}}；不要直接照搬其他发行版新增的占位符。
\end{example}

\begin{note}
日志不及时，应区分 ROS 控制台缓冲、Python 的 print 缓冲和 Launch 输出转发，不能统一靠设置“缓冲为 1”解决。Humble 教学流程使用启动时的 \texttt{--log-level}；不要假设所有安装都存在 \texttt{ros2 logger set} 命令或运行时 logger 服务。编译时已移除的 DEBUG 宏也无法靠运行参数恢复。
\end{note}
\begin{exercise}
将 heartbeat 的 INFO 限流间隔改为 1000 毫秒，保留定时器 200 毫秒。分别预测并测量消息频率与 alive 日志频率；解释改为 WARN 阈值后消息是否停止。
\end{exercise}

\subsubsection{CLion：让编辑、构建和运行使用同一套环境}
\label{sec:ros2-clion}

IDE 找到头文件需要构建配置，运行程序还需要动态库和 ROS 环境。两者都要检查。关键不是“只能从终端打开”，而是 IDE 的 CMake、运行配置确实继承或加载了正确环境。可用已加载环境的终端启动，也可配置 IDE 环境脚本或启动包装脚本。

\begin{example}[从可运行的终端进入 IDE]
先用终端成功构建 training\_tools；关闭已运行的 CLion 实例，避免启动命令把项目交给旧环境中的实例。若安装时已创建 \texttt{clion} 命令，执行：
\begin{tbash}
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
clion ~/ros2_ws/src/training_tools
\end{tbash}
没有该命令时，使用安装目录内的实际启动脚本路径。打开包中的 CMakeLists.txt，在 CMake 配置中使用独立目录 \texttt{cmake-build-debug}、Debug 构建类型和 \texttt{-DBUILD\_TESTING=OFF}。选择 heartbeat 目标，运行参数填 \texttt{--ros-args -p text:=from\_ide}，在发布回调处加断点。继续执行后，用已加载相同环境的终端观察 \texttt{/status}。
\end{example}

CLion 的 Build 只负责所选构建目标。设置 \texttt{CMAKE\_INSTALL\_PREFIX} 仅改变安装目的地，不会自动执行安装。需要从 \texttt{ros2 run} 启动修改后的代码时，应由 colcon 重建并安装，或明确执行 IDE 的 install 目标；同时确认运行时加载的是该安装前缀。调试 IDE 构建目录中的目标时，则直接使用该目标。

\paragraph*{用编译数据库浏览多包工程}
编译数据库（compilation database）记录每个翻译单元实际使用的编译器、宏和头文件搜索路径，适合让 IDE 按 colcon 的真实参数索引代码。

\begin{example}[生成并核对索引来源]
\begin{tbash}
cd ~/ros2_ws
colcon build --packages-select training_tools --cmake-args -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
test -f build/training_tools/compile_commands.json
\end{tbash}
在 CLion 中以编译数据库项目打开这个 JSON，核对 heartbeat.cpp 的包含路径。它只涵盖该包；修改项目根目录不会自动合并其他包的编译数据库。接口包须先构建，生成的消息头文件才存在。需要整个工作空间索引时，应显式收集各包的数据库并按工具支持方式合并。
\end{example}

\begin{conclusion}
\begin{itemize}
\item 找不到 ament：检查 IDE 环境；找不到生成接口头：先构建接口包。
\item CLion 与 colcon 使用不同构建目录，避免 CMake 缓存和生成器相互覆盖；两者不必强制使用同一种生成器。
\item 断点不命中：检查 Debug 配置、正在运行的二进制路径，以及代码是否重新构建。
\item build、install、log、\texttt{.idea}、\texttt{cmake-build-*} 和生成的编译数据库通常不提交 Git；源码、清单和启动配置需要提交。
\end{itemize}
\end{conclusion}
\begin{exercise}
在 IDE 中把默认文本改为 \texttt{from\_debug} 并构建；分别从 IDE 和旧安装目录运行。解释为何可能看到不同文本，给出让 \texttt{ros2 run} 使用新代码的步骤。
\end{exercise}
