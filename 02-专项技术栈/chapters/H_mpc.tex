前两章里，我们把抖动的观测变成了状态估计，又把图像点和空间位姿联系起来。不过，算出一个角度，并不等于云台已经转到那里：你发出指令后，电机还要加速、减速，通信和计算也要花时间。如果目标已经走了，云台还在追上一帧的位置，几何算得再漂亮也帮不上忙。

这时候，我们需要把“接下来想去哪里”和“执行器来不来得及”一起考虑。模型预测控制（Model Predictive Control，MPC）会先预测一段运动，找出满足约束的输入，再根据新状态继续规划。本章沿用原来能手算的一步例子，然后搭一个真正求解有限时域二次规划（Quadratic Programming，QP）的小项目。全部实验只在离线模型里运行，真实云台参数、弹道和开火判定留到卷三。

\subsubsection{信号与系统：指令是怎么变成运动的}

\paragraph*{先分清你发给了谁}
如果输入是电机力矩$\tau$，单轴惯量和黏性阻尼的简化模型为
\[
J\ddot\theta+B\dot\theta=\tau.
\]
J是转动惯量，B是阻尼系数；这里忽略摩擦、间隙等效应。零初始条件下，拉普拉斯变换给出$\Theta(s)/\mathcal{T}(s)=1/[s(Js+B)]$。如果驱动器已经有速度环，而你发的是角速度指令，那么可以在适用的频段内用
\[
\frac{\Theta(s)}{U(s)}=\frac{K}{s(Ts+1)}
\]
近似“速度环的一阶滞后，再积分成角度”。这两个输入的含义不同，不能因为都叫u，就把系数直接互换。

传递函数（transfer function）方便我们在零状态条件下描述输入输出关系；状态空间还可以把当前角度、角速度等初始状态带进去。先别急着找一套特别复杂的电机模型，我们从能看出滞后的离散系统开始：
\[
y[k+1]=a y[k]+(1-a)u[k],\qquad 0\le a<1.
\]
它是归一化的一阶响应例子，不能替代上面的力矩模型。取$y[0]=0,u[k]=1$，有$y[k]=1-a^k$。a越接近1，旧状态占的比重越大，接近目标也越慢。

\subsubsection{幅度、相位与延时：慢在哪里}

\paragraph*{从一根正弦波开始}
对于线性时不变（Linear Time-Invariant，LTI）系统，我们可以先考察不同频率的正弦输入。稳定且存在相应稳态时，输入$\sin(\omega t)$的稳态输出写成$A(\omega)\sin[\omega t+\phi(\omega)]$。A是幅频特性，$\phi$是相频特性。满足变换条件的信号可以分解成频率分量，再利用线性叠加；初始过渡、饱和和时变系统不能随手装进这个结论。

项目里按$u[k]$对$y[k]$定义频响，令$z=e^{\mathrm j\Omega}$，$\Omega=2\pi f\Delta t$，则
\[
G(z)=\frac{1-a}{z-a}.
\]
代码\texttt{H=(1-a)/(exp(2j*pi*f*dt)-a)}保留了从k到k+1的时间约定。把它错写成别的索引关系，幅值可能仍像那么回事，相位却会差一拍。

\begin{example}[同样的滞后，未必是同一种改变]
纯延时$T_d$的频响是$e^{-\mathrm j\omega T_d}$，幅值1、相位$-\omega T_d$。取20ms，1/10Hz相位约为$-0.126/-1.257$rad；相位角不同，时间延迟却相同。response的delayed按这条公式生成，表示已经存在的连续稳态信号整体后移，并没有给它加启动过渡。

而一阶模型a0.8、采样10ms在1/10Hz的幅值约0.963/0.340，相位约$-0.307/-1.555$rad。它让两频率的比例改变，因此叠加波形也变了。图\ref{fig:v2-mpc-response}左边看接近目标的快慢，右边看“整体后移”和“形状改变”的区别；实际逐步递推后的稳态拟合也独立核对了这些增益与相位。
\end{example}

\centering
\includegraphics[width=.94\textwidth]{images/mpc_response_revised.pdf}
\caption{实际保存的一阶阶跃与两频率稳态数组；右图分别显示输入、纯延时和一阶输出，不能把稳态图当作启动过程。}

\end{figure}

\end{exercise}

\paragraph*{阶跃指标与物理限制}
阶跃常用上升时间、超调量、调节时间和稳态误差来描述。比较时要声明标准，例如进入并保持在最终值的2\%范围内；本项目的一阶单调响应可直接数首次达到0.98的步数，存在振荡的响应则不能只找第一次穿线。

幅频失真来自不同频率的增益不同，相频失真来自不能归为统一延时的相位关系。惯性、带宽和采样都会影响响应，摩擦/间隙等非线性又有自己的条件；结构共振也可能出现在仍然线性的模型里，不能一律归成非线性失真。你调高增益时看到抖动，先看测量、模型和频段，再决定从哪里改，别给PID旋钮加上“越大越强”的游戏属性。
\begin{conclusion}
幅值告诉你跟到了多大，相位告诉你各分量落后多少。纯延时保留形状但让整个信号迟到；一阶滞后同时改变增益和相位。频响描述有条件的LTI响应，阶跃看过渡，饱和与间隙需要另外分析。
\end{conclusion}

\subsubsection{误差容限与执行器来不来得及}
取简化点目标模型，有效宽度L、距离d对应几何半角
\[
\epsilon=\arctan\frac{L}{2d}\approx\frac{L}{2d}.
\]
小角度近似用rad；这个几何量只帮助比较尺度，没有把目标运动、弹丸飞行、标定误差和判定规则一起算进去，不能直接当实车开火条件。
\begin{example}[还是原来的0.1m与5m]
\begin{tbash}
python response.py --distance 5 --output out/near
python response.py --distance 10 --output out/far
\end{tbash}
前者约0.0099997rad，即0.573°，后者约0.005rad。你把距离加倍，同样宽度在画面里就更窄，同样角度误差也更容易落到外面。
\end{example}
\begin{exercise}\label{ex:v2-mpc-tolerance}
核对10m时的半角和角度值。对于固定角度误差0.008rad，分别换算5/10m处的横向偏移，解释它与几何宽度的关系。
\end{exercise}

对参考$r(t)=A\sin\omega t$，精确跟随需要最大速度$A\omega$和最大加速度$A\omega^2$，因此至少满足
\[
A\omega\le\omega_{\max},\qquad A\omega^2\le a_{\max}.
\]
这里$\omega_{\max}$是执行器角速度上限，$\omega$是信号角频率，两个符号长得像，单位和含义却要分开。对于已经辨识的稳定LTI闭环，稳态误差幅度还可写为$A|1-G(\mathrm j\omega)|$，再与$\epsilon$比较。这是特定模型和稳态条件下的响应包络，不能宣称仅凭两个物理上限就证明任意控制器的误差。
\begin{example}[先排除根本跟不上的参考]
取$\omega_{\max}=0.8$rad/s、$a_{\max}=2$rad/s$^2$、A=0.1rad、f=2Hz，精确跟随要求约1.257rad/s和15.79rad/s$^2$，两项都超限。换成f=0.5Hz，需要约0.314/0.987，满足这两项必要条件，但还没有证明实际跟踪误差合格。
\end{example}
\begin{exercise}\label{ex:v2-mpc-envelope}
保持上述上限，在1Hz时分别求速度、加速度允许的最大A，并取更小者。这个数是否已经证明稳态误差不超过0.01rad？还缺什么信息？
\end{exercise}

\subsubsection{把规划问题写清楚}
MPC的目标是让未来预测误差小，同时不过度使用输入，并把约束写进求解。它和最小二乘共享一些数学形式，但优化变量是控制序列；Kalman在估计状态，BA在拟合几何，不能把三者说成同一个任务。跟踪误差小也不能直接等同于命中率最优，真实链路还要考虑那些没有写进当前模型的因素。

\paragraph*{明确这次u的单位}
项目状态为$x=[\theta,\omega]^T$，单位rad、rad/s，u是一个采样周期内保持的角加速度，单位rad/s$^2$。采样$\Delta t=0.05$s，从连续关系$\dot\theta=\omega,\dot\omega=u$得到
\[
x_{k+1}=Ax_k+Bu_k,\quad
A=\begin{bmatrix}1&\Delta t\\0&1\end{bmatrix},\quad
B=\begin{bmatrix}\Delta t^2/2\\\Delta t\end{bmatrix},\quad y_k=[1\ 0]x_k.
\]
这是保持输入条件下的精确离散模型，不是已测量的云台动力学。若你的驱动器接收速度、位置或力矩，需要先确定对应模型和接口，再决定控制量怎样发送。
\begin{example}[先让模拟执行器走一步]
\path{model.py}统一这一层，\texttt{gain}只在模拟真实对象时改变加速度，用来制造“控制器相信的模型与实际对象不一致”：

\end{example}

\subsubsection{真正求一段未来轨迹}
在时刻k，我们规划$U=[u_k,\ldots,u_{k+N-1}]^T$，堆叠未来状态$X=[x_{k+1}^T,\ldots,x_{k+N}^T]^T$，有
\[
X=\Phi x_k+\Theta U,\qquad
\Phi_i=A^{i+1},\quad
\Theta_{ij}=\begin{cases}A^{i-j}B,&j\le i,\\0,&j>i,\end{cases}
\]
这里i/j从0开始，每块两行。想只看角度输出，就选每个状态的第一行；项目同时用角速度建立代价和约束，因此保留完整X。
\begin{example}[堆叠矩阵不是凭名字生成的]
\path{prediction.py}按照上式逐块放入；第一个输入会影响整个后续预测，最后一个只影响最后状态：
\needspace{8\baselineskip}
\lstinputlisting[language=Python,numbers=left,basicstyle=\footnotesize\ttfamily]{examples/mpc/horizon-control-demo/prediction.py}
N=2时$\Theta$为
\[
\begin{bmatrix}.00125&0\\.05&0\\.00375&.00125\\.05&.05\end{bmatrix}.
\]
本次用N1/2/15与独立逐步递推核对，最大差接近机器精度。做完这一层，才知道求解器收到的“未来”与模拟器是不是同一个未来。
\end{example}

\paragraph*{从平方代价到二次规划}
每步参考状态为$[r,0]^T$，角度跟r、角速度希望回到0。项目把角度权重取20，角速度取0.5，输入取0.1，再按N步重复，得到
\[
\bar Q=\operatorname{diag}(20,0.5,\ldots),\qquad \bar R=0.1I.
\]
将参考堆叠称为$X_{ref}$，避免与输入权重R混淆。于是
\begin{align*}
F(U)&=(X-X_{ref})^T\bar Q(X-X_{ref})+U^T\bar R U\\
&=\tfrac12U^THU+g^TU+c,\\
H&=2(\Theta^T\bar Q\Theta+\bar R),\quad
 g=2\Theta^T\bar Q(\Phi x_k-X_{ref}).
\end{align*}
c与U无关，所以求最优输入时可以略去；报告完整代价时要加回。不同单位的状态需要相应权重，20和0.5只是当前模型的设计选择，不是通用调参答案。正输入权重让本例H正定，不能用“求解器没报错”代替凸性判断。

OSQP使用$\min\frac12U^THU+g^TU$、$l\le DU\le h$的接口。加速度用I U约束，角速度用$\Theta$的奇数行和$\Phi x_k$的偏移约束；若加硬终点角度，就再加一行等式。\href{https://osqp.org/docs/interfaces/python.html}{官方Python接口}说明CSC稀疏矩阵及返回值，\href{https://osqp.org/docs/interfaces/status_values.html}{状态表}帮你区别solved、infeasible和迭代上限。本项目按实际1.0.4接口核对，不假定不同版本参数名完全一样。

\subsubsection{滚动执行、失败与时效}
求出N个输入后，我们只执行第一个。下一轮拿新状态重做预测，这样扰动才有机会进入反馈。不过，如果这一轮迟到了，状态已经变了，旧的“最优”也可能不适合现在。

\needspace{8\baselineskip}
\lstinputlisting[language=Python,numbers=left,basicstyle=\footnotesize\ttfamily]{examples/mpc/horizon-control-demo/controller.py}
预算默认10ms，输入年龄上限100ms；这些是教学实验的约定。计时包含QP构造、setup、solve及检查，Python启动和导入在循环前。\texttt{work\_ms}会真的等待以制造超时，没有伪造返回状态或时钟；它不是最坏执行时间证明。OSQP自身\href{https://osqp.org/docs/interfaces/solver_settings.html}{time\_limit设置}也不能代替整个处理链截止时间。

\begin{example}[确实发生失败，再检查实际输出]
\begin{tbash}
python run.py --horizon 2 --terminal --steps 3 --output out/infeasible
python run.py --max-iter 1 --steps 3 --output out/maxiter
python run.py --work-ms 20 --steps 3 --output out/late
python run.py --age-ms 200 --steps 3 --output out/stale
\end{tbash}
terminal加硬终点，max-iter限制实际求解迭代，work-ms为额外真实等待，age-ms让采集时间确实比当前单调时钟早。本次分别得到primal infeasible、maximum iterations reached、deadline、stale\_input。后两者仍可能solved，控制输出却全部回退；这次初始静止，回退为0。最慢超时轮约21.63ms，不能拿求解器较短的内部时间说它赶上了10ms预算。

默认一轮本次最大约1.61ms，只能证明当前机器的这次离线运行；采集2ms、求解5ms、发送1ms共8ms的原算例仍成立，但真实发送、系统调度和更坏输入没有在此测量。在线控制需按整个链路测试截止时间，不能把这组桌面数字当作实时保证。
\end{example}

\subsubsection{接到实际控制链时还要注意什么}
首先统一参考轨迹的坐标、时间和单位。Kalman给的是状态与不确定性，参考还需要预测时刻和弹道处理；不确定性大时如何调整跟踪权重是设计选择，降低Q并不会自动证明稳定或改善任务效果。

然后看清接口。这里u是加速度，不能直接称为前馈力矩；若要叠加反馈、摩擦补偿或内环，需要说明由哪个模块换算、限幅在哪里做，并把合成输入的效果纳入模型或验证。反馈带来修正机会，并不保证任意模型误差都能被消掉。
\begin{example}[改实际增益，以及在规划后偷偷加一层低通]
\begin{tbash}
python run.py --gain 0.6 --output out/mismatch
python run.py --command-alpha 0.1 --output out/filtered
\end{tbash}
gain0.6时，本次最终角度约0.400379rad、RMSE0.1323，比默认慢一些。这里只改一个增益，没有证明对所有摩擦、间隙和延迟都鲁棒。

alpha0.1则让实际输入$u^{act}_k=0.1u_k+0.9u^{act}_{k-1}$，预测仍假定直接执行u。虽然实际输入不超过2，最大速度却约0.8203rad/s，越过0.8，4s时角度约0.6098rad。图\ref{fig:v2-mpc-filter}能看到来不及刹住的过程：规划满足的是原模型，滤波后对象走的却是另一条轨迹。若需要这层滤波，应把滤波器状态纳入预测模型并重新验证约束与闭环，而不是只说“曲线平滑所以更安全”。
\end{example}

\begin{conclusion}
MPC会看未来，也要接受现实：预测模型、输入接口和真实执行链须一致；这一轮只执行首个输入，下一轮以新状态重新规划。额外滤波、补偿、调度和时戳都会改变实际结果。先保存并核对模型、输入、约束与失败日志，再讨论上车；求解器的solved没有替你完成这一整条链。
\end{conclusion}
