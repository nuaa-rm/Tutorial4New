\section*{第一章：ROS2 基础}

\subsubsection*{随堂练习}

\paragraph*{随堂练习 \ref{ex:v2-ros-setup}}
\begin{solution}
talker 属于 \texttt{demo\_nodes\_cpp}。加载当前发行版环境后，可执行：
\begin{tbash}
ros2 pkg executables demo_nodes_cpp
ros2 run --help
ros2 run demo_nodes_cpp talker
\end{tbash}
前两条分别确认包中的可执行程序与启动语法，第三条启动发布节点。按 Ctrl+C 结束。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-ros-graph}}
\begin{solution}
在只启动一个示例 talker 的环境中，\texttt{/chatter} 类型为 \texttt{std\_msgs/msg/String}，发布者数量通常为 1。
\begin{tbash}
ros2 topic info /chatter
ros2 node list
\end{tbash}
停止 talker 后等待发现信息更新，发布者数量应变为 0，或话题不再列出；如果 echo 等订阅者仍在运行，话题可能仍可见。节点是功能实体，话题是通信通道，不能用“还能查到话题”判断发布节点是否存活。
\end{solution}


\paragraph*{随堂练习 \ref{ex:v2-ros-qos}}
\begin{solution}
可靠发布者能够满足 best\_effort 订阅者的要求，所以可以通信。发布端和订阅端按“提供的策略是否满足要求”匹配，不要求每项值都相等。分别运行：
\begin{tbash}
# 终端一
ros2 topic pub /qos_demo std_msgs/msg/String "{data: hello}" --rate 1 --qos-reliability reliable
# 终端二
ros2 topic echo /qos_demo std_msgs/msg/String --qos-reliability best_effort --once
\end{tbash}
应收到 hello。这里只改变可靠性，其他策略保持兼容；不能由这个实验推断任何 QoS 组合都能通信。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-ros-message}}
\begin{solution}
在 \texttt{my\_msgs/msg/My.msg} 末尾加入 \texttt{float64 distance}，保存后回到工作空间根目录：
\begin{tbash}
cd ~/ros2_ws
colcon build --packages-select my_msgs
source install/setup.bash
ros2 interface show my_msgs/msg/My
\end{tbash}
应看到新增字段。若节点要访问该字段，再重新构建依赖它的包，例如执行 \texttt{colcon build --packages-up-to my\_package}。单位约定为米，应同时写在接口注释或文档里。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-ros-timer}}
\begin{solution}
将构造函数中的间隔改为 \texttt{std::chrono::milliseconds(500)}，重新构建、加载环境并重启节点。在另一个已加载环境的终端执行：
\begin{tbash}
ros2 topic hz /timer_
\end{tbash}
理论频率为 2 Hz，调度和观测窗口会造成小幅波动。计数器只表示回调执行次数；时间戳表示特定时钟下的事件时间。间隔改变后，一次计数不再等于一秒，不能用计数器代替时间戳。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-ros-service}}
\begin{solution}
服务端运行时查询：
\begin{tbash}
ros2 service list -t
ros2 interface show example_interfaces/srv/AddTwoInts
\end{tbash}
请求包含两个 \texttt{int64} 字段 a、b，响应包含 \texttt{int64 sum}；接口中的三条短横线分隔请求和响应。服务对应一次请求与一次响应，话题用于按发布端节奏持续传递数据，两者用途不同。
\end{solution}


\paragraph*{随堂练习 \ref{ex:v2-ros-reply}}
\begin{solution}
receive 与 send 都使用 \texttt{std\_msgs/msg/String}。先保持 \texttt{ros2 topic echo /send} 运行，再在另一终端发送：
\begin{tbash}
ros2 topic pub --once /receive std_msgs/msg/String "{data: armor_found}"
\end{tbash}
应收到 \texttt{I can hear:armor\_found}。停止节点后，原命令可能等待订阅者；加 \nolinkurl{--wait-matching-subscriptions} 并设为 0，可以在没有订阅者时也发送一次，但不会收到回复。CLI 打印 publishing 只说明发布端执行了发送，处理是否发生要由回调日志、响应消息等证据确认。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-ros-domain}}
\begin{solution}
域不同的两个节点不能按普通 DDS 发现互相通信；统一为 42 后应恢复收发。两端都先停止节点，再设置相同的 \texttt{ROS\_DOMAIN\_ID} 和发现范围，执行 \texttt{ros2 daemon stop} 并重新启动。恢复默认实验环境时停止节点、unset \texttt{ROS\_DOMAIN\_ID}、\texttt{ROS\_LOCALHOST\_ONLY}、\nolinkurl{ROS_AUTOMATIC_DISCOVERY_RANGE} 和 \texttt{ROS\_STATIC\_PEERS}，停止 daemon 后重新运行；持久写入启动文件的设置也需删除或更改。域隔离实验须排除同名遗留发布者。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-ros-ament}}
\begin{solution}
启动系统通常从安装索引查资源。检查 CMake 是否安装 launch/config 目录、是否重新构建，以及当前环境是否指向该工作空间。手动版本应包含：
\begin{tcode}
install(DIRECTORY launch config DESTINATION share/${PROJECT_NAME})
\end{tcode}
间隔函数改为 \texttt{milliseconds >= 10 \&\& milliseconds <= 500}；合法边界测试为 10 和 500，非法测试为 9 和 501。\Needspace{11\baselineskip}
保存后执行：
\begin{tbash}
cd ~/ros2_ws
colcon build --packages-select training_tools --cmake-args -DBUILD_TESTING=ON
source install/setup.bash
colcon test --packages-select training_tools
colcon test-result --verbose
ros2 pkg prefix training_tools
\end{tbash}
预期边界测试全部通过，包前缀指向当前工作空间的安装目录。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-ros-launch}}
\begin{solution}
在 team 文件中将 observer 的 cmd 改成下面的列表，其余配置保持不变。嵌套列表把三个替换片段拼成同一个话题参数：
\begin{tpython}
cmd=['ros2', 'topic', 'echo',
     ['/', LaunchConfiguration('robot'), '/health'],
     'std_msgs/msg/String', '--once'],
\end{tpython}
重新构建、加载环境后运行：
\begin{tbash}
ros2 launch training_tools team.launch.py robot:=blue
\end{tbash}
应看到一条 team ready 消息及观测进程退出提示，heartbeat 继续运行。结束后再次启动：
\begin{tbash}
ros2 launch training_tools team.launch.py robot:=blue watch:=false
\end{tbash}
此时不启动 echo 进程。用另一个终端查询 \texttt{ros2 node list}、\texttt{ros2 topic info /blue/health}，应确认 heartbeat 发布者存在；查询命令本身可能产生临时观测节点，不能仅凭节点总数判断。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-ros-log}}
\begin{solution}
定时器仍为 200 毫秒，所以理论消息频率是 5 Hz；alive 限流改成 1000 毫秒后约为 1 Hz。修改源码、重新构建、加载环境并重启后，用 \texttt{ros2 topic hz /status} 测量前者，按日志时间戳检查后者。调度、观测窗口和所用时钟会影响实测间隔。WARN 阈值仅隐藏 INFO/DEBUG 日志，发布逻辑仍运行，不会因此停止消息。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-ros-ide}}
\begin{solution}
IDE 默认运行独立构建目录中的目标，\texttt{ros2 run} 根据已加载环境运行安装目录中的目标。仅执行 IDE Build 时，安装目录可能仍是旧程序。先去掉运行配置中的 \texttt{-p text:=from\_ide} 等文本覆盖，才能观察修改后的默认值；否则参数会掩盖源码默认值的变化。停止旧进程，然后执行：
\begin{tbash}
cd ~/ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select training_tools
source install/setup.bash
ros2 pkg prefix training_tools
ros2 run training_tools heartbeat
\end{tbash}
确认包路径属于当前工作空间，观察 /status 应得到 from\_debug。若仍是旧值，检查是否有其他发布者、参数覆盖、同名覆盖包，以及实际改动的源码路径。
\end{solution}

\end{solution}

\end{solution}

\section*{第二章：多机通信方法}
\phantomsection
\addcontentsline{toc}{section}{第二章题解：多机通信方法}
\subsubsection*{随堂练习}

\paragraph*{随堂练习 \ref{ex:v2-comm-boundary}}
\begin{solution}
可让相机处理进程作为 Server、记录进程作为 Client，使用本机 TCP；协议约定长度、字段类型/编码、序号、时间、单位与坐标系。跨机器还约定地址与访问控制。设备由一个明确进程读取后分发完整帧，否则两个读取者可能分别拿走部分字节，双方都无法组帧。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-comm-roles}}
\begin{solution}
Server 执行 bind、listen、accept，Client 执行 connect；随后双方都能收发。把 ping 改成 pong 仍输出 pong。改为两字节后还要关闭发送方向，否则只是暂时没收满，会等待到超时：
在 Python 源码中修改为下面两行：
\begin{tpython}
client.sendall(b"po")
client.shutdown(socket.SHUT_WR)
\end{tpython}
接收累计到两字节后，下一次 recv 得到空字节，抛出“连接提前关闭”；不能把 po 当完整四字节结果。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-comm-fragments}}
\begin{solution}
把 \texttt{parser\_demo} 中的输入列表替换为：
\begin{tpython}
[b"\x02", b"A", b"B", b"\x03X", b"YZ"]
\end{tpython}
输出仍为 AB、XYZ。向 LengthParser.feed 输入零长度会抛出 ValueError 并清空缓存，TCP 服务端据此结束本连接。协议没有可靠帧头，后面某个载荷字节也可能像合法长度，跳过一个字节再猜会误组帧。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-comm-latest}}
\begin{solution}
priority 改为 status、position 后，第一次 take 得到 status/ready，第二次得到 position/30，槽数随后为零；调整原来只检查位置的断言和输出。代次 1 的迟到清理应记录当前代次 2、返回 False，位置 42 保留；代次 2 清理返回 True，清空自身状态。实际共享状态的检查与修改要在同一保护范围内，日志的状态读取也应同步。运行后面的两轮 TCP，第二轮同样拒绝代次 1 清理并继续回显。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-comm-events}}
\begin{solution}
把丢确认条件改为 \texttt{event[0] == 1}，不再限定 attempt 为 1。第 1 事件发送三次，实际只执行一次，每次确认都丢失；最终 RuntimeError 报告投递失败，程序不会继续处理第 2 事件。发送端失败并不证明接收端没执行，应通过约定的查询/确认处理不确定结果。原示例只丢第一次时，第 1 事件第二次得到确认，第 2 事件也完成。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-comm-crc}}
\begin{solution}
不要重算损坏帧的 CRC。在 \texttt{parser\_demo} 构建 stream 处改为：
\begin{tpython}
damaged = bytearray(encode_crc(7))
damaged[1] ^= 1
stream = b"noise" + bad + damaged + encode_crc(9)
\end{tpython}
值列表应为 [9]，坏 CRC 计数为 2，最后 buffer 为空；同步修改原本期待 [7] 与一次坏 CRC 的断言。改完数据又重新算 CRC，得到的是另一条有效帧，不能测试拒收损坏载荷。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-comm-units}}
\begin{solution}
\texttt{bridge\_demo} 中 struct.pack 的输入改为 (8, 2000)。普通模式输出 (8, 2.0)，ROS 的 /\texttt{range\_m} 输出 data: 2.0；换程序前停止旧节点，避免两发布者混在一起。换算在协议边界做一次，内部统一使用米。位置接口还需明确坐标轴/坐标系、时间来源、单位、序号与无效值；Float64 的类型本身不会帮你约定这些内容。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-comm-isolation}}
\begin{solution}
A 最后一次输入在第 1 秒，第 4 秒年龄为 3。阈值 4 时不过期，应得到 position/11，expired 保持 0；相应修改演示中原本期待 None 和计数 1 的断言，并把过期提示改为“旧值仍被允许”。恢复阈值 2 时丢弃一次。B 始终消费 100--105；A 槽数最多 1，第 5 秒消费新值 15。比较是大于阈值，所以年龄恰好等于阈值时仍允许消费。
\end{solution}

\subsubsection*{章末习题}
\paragraph*{第二章章末第 \ref{prob:v2-comm-1} 题}
\begin{solution}
不应争抢设备读取。由唯一所有者校验组帧，再向其他进程分发完整消息；发送控制命令也按同一接口约定协调。
\end{solution}
\paragraph*{第二章章末第 \ref{prob:v2-comm-2} 题}
\begin{solution}
客户端 connect，服务端 accept 得到新连接对象，通过它收发；监听对象继续负责接入连接。
\end{solution}
\paragraph*{第二章章末第 \ref{prob:v2-comm-3} 题}
\begin{solution}
不能。两条连接的数据没有组成同一帧的约定，拼起来可能混合不同轮次或不同客户端的数据。丢弃旧半帧，新连接另建解析器。
\end{solution}
\paragraph*{第二章章末第 \ref{prob:v2-comm-4} 题}
\begin{solution}
校验失败说明候选帧不满足协议，拒收并按规则重同步；CRC 不验证身份，也不能替代鉴权。
\end{solution}
\paragraph*{第二章章末第 \ref{prob:v2-comm-5} 题}
\begin{solution}
填 3.0 m/s，还需约定速度向量的坐标系、采集时间与时钟来源。不能把接收时间冒充源采集时间，也不能重复换算。
\end{solution}
\paragraph*{第二章章末第 \ref{prob:v2-comm-6} 题}
\begin{solution}
检查之后、关闭之前可能已换连接；在锁外重新读取当前 socket，就会关掉新对象。比较代次和摘下本轮归属要一起受保护，关闭保存的旧对象，不再读取当前对象。槽位写入和清理也遵守同样规则。
\end{solution}
\paragraph*{第二章章末第 \ref{prob:v2-comm-7} 题}
\begin{solution}
只消费最新值 300；三次购买需有界事件队列，约定确认、重试、序号去重及满队列/失败处理，不能覆盖成一次。
\end{solution}
\paragraph*{第二章章末第 \ref{prob:v2-comm-8} 题}
\begin{solution}
原示例第 1 事件发送 2 次、执行 1 次、确认成功；第 2 事件发送/执行各 1 次。所有确认都丢时，第 1 事件发送 3 次、执行 1 次，发送端失败并停止，第二事件尚未执行。检查日志中实际执行与发送次数，失败不能推出对方未执行；需要查回结果或按协议处理不确定状态。
\end{solution}
\paragraph*{第二章章末第 \ref{prob:v2-comm-9} 题}
\begin{solution}
年龄为 3 秒，超过 2 秒阈值，应丢弃、计数并按约定使用新鲜备用源。不同时间原点和未同步时钟不能直接相减；接收年龄使用本机同一单调时钟，跨机采集时间另行约定同步与误差范围。
\end{solution}


\section*{第三章：SDR 与电磁波解析}

\subsubsection*{随堂练习}

\paragraph*{随堂练习 \ref{ex:v2-sdr-boundary}}
\begin{solution}
天线和 ADC 在硬件采集端；前导相关、CRC 在数字接收端；坐标换算在校验后的字段接口。IQ 录包可以重放数字补偿、相关、判决、组帧、校验及字段转换，不能补回模拟滤波损失，也不能单靠它验证天线位置、接地、模拟饱和、调谐稳定或实时丢样。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-sdr-iq}}
\begin{solution}
相邻相位差主值分别为 $\pi/8$、$-\pi/8$、$-7\pi/8$，约 0.392699、-0.392699、-2.748894 rad，幅值仍为 1。9000 Hz 在 16000 Hz 采样下等价于 -7000 Hz，与 1000 Hz 不再相同。将原断言改为比较负 7000 Hz：
\begin{tpython}
assert np.allclose(iq, np.exp(2j * np.pi * (-7000) * n / fs))
\end{tpython}
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-sdr-record}}
\begin{solution}
正常样本数 670，采样率 8000 Hz，每符号 8 个样本，本机 dtype 为 \texttt{<c8}，另有已知频偏 125 Hz 与文件 SHA-256。只改 \texttt{sample\_count} 不影响 IQ 文件哈希，因此先通过哈希检查，再在数量与元数据比较处拒绝。\texttt{.npy} 有文件头，不能从第一个字节开始按裸 float32 读；要用 \texttt{np.load(..., allow\_pickle=False)} 恢复复数数组，再分别取 real/imag。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-sdr-sync}}
\begin{solution}
前导相关的相角估计约为 $\pi$，补偿后符号回到正确实轴，起点仍为 19，坐标仍是 (1.25,2.5) 米。若保留频偏补偿但跳过恒定相位补偿，实部符号翻转，已知前导比较失败；若绕过前导检查继续解析，CRC 通常也失败。不能把“通常”当成认证保证，正确流程不允许绕过这些检查。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-sdr-crc}}
\begin{solution}
2000 mm 的正常录包交付 x=2.0 m、y=2.5 m、序号 7。生成器按新载荷重算 CRC 才能得到一致帧；加 \texttt{--corrupt} 后先算 CRC 再修改载荷，回放应报告 CRC 失败而不交付字段。若损坏实验也重算 CRC，就造出了一条新的有效帧，无法证明拒收路径。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-sdr-stages}}
\begin{solution}
序列对应 level2/1、level1/2、level1/2、level2/3、information/4（斜线后为代次）。reset 后来自旧代次的结果应拒绝，不因当前阶段名字恰好相同就接受。实机还需由唯一设备所有者更新配置、清空旧缓冲、等待稳定；模拟代码中的计数只验证状态关系。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-sdr-fresh}}
\begin{solution}
radio 年龄为 -0.1 s，被非负年龄条件拒绝；vision=9.9 s 时仍选择 vision。再将 vision 改为 9.0 s，应返回 None，将原第一个断言相应改为 \texttt{is None}。上层收到明确的“无有效源”状态并采用约定回退，不能把旧位置冒充当前测量。None 并不自动等于整车急停，具体行为由业务和实车安全策略决定。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-sdr-capture}}
\begin{solution}
无硬件时记录实际 pyadi-iio/libiio 版本、导入结果、帮助参数和设备未验证，不能把这几项写成 RX 成功。有设备时需实际展示 URI、批准的接收配置、4096 样本的形状与 dtype、采样率/本振读回、录包元数据及缓冲清理；异常应保留原因。真实波形不一定采用本例前导、BPSK、8 样本/符号或已知频偏，必须有实际协议与同步设计，不能凭“都是 IQ”就套用教学 decode。
\end{solution}

\subsubsection*{章末习题}
\paragraph*{第三章章末第 \ref{prob:v2-sdr-1} 题}
\begin{solution}
两者都不能凭软件保证恢复：滤掉的频段未被记录，ADC 饱和会将不同输入压成相同或受限的输出。先改前端带宽、增益或输入条件，再重新采集；回放只能处理已留下的信息。
\end{solution}
\paragraph*{第三章章末第 \ref{prob:v2-sdr-2} 题}
\begin{solution}
幅值为 5。只保留幅值会丢失相位及其旋转方向，理想正、负频率单音都只剩相同常幅值，不能还原完整复数信号。
\end{solution}
\paragraph*{第三章章末第 \ref{prob:v2-sdr-3} 题}
\begin{solution}
符号率为 1000 符号/秒，BPSK 每符号 1 比特，故比特率为 1000 bit/s（此例没有编码开销）。一帧含 16 比特前导和 64 比特数据/CRC，共 80 符号，即 640 样本；录包额外有 30 个空样本，总数才是 670。
\end{solution}
\paragraph*{第三章章末第 \ref{prob:v2-sdr-4} 题}
\begin{solution}
哈希检查文件字节，不检查“这些字节每秒产生多少个”的真实性。完整约定至少记录采样率、类型与字节序/文件格式、数量、I/Q 顺序、调谐与增益、来源、采集时间及校验值；回放还应核对实际配置和波形的已知特征。裸文件与带头的 .npy 必须区分，哈希也不能当作来源认证。
\end{solution}
\paragraph*{第三章章末第 \ref{prob:v2-sdr-5} 题}
\begin{solution}
同步确定样本起点与相位/频率参考；符号均值和判决得到比特；CRC 检查候选帧的载荷与校验值是否一致。CRC 不保证身份、坐标系、单位或新鲜度，上层仍需各自验证。
\end{solution}
\paragraph*{第三章章末第 \ref{prob:v2-sdr-6} 题}
\begin{solution}
恒定相位是固定角度，乘一个反向旋转即可抵消；频偏使相位随时间增长 $2\pi\Delta f t$，只抵消起点角度后，后续仍会继续转。本例按元数据的已知频偏逐样本补偿，真实接收机还需要估计与跟踪频偏。
\end{solution}
\paragraph*{第三章章末第 \ref{prob:v2-sdr-7} 题}
\begin{solution}
检查结果附带的 profile/代次与当前任务是否一致，旧代次不得更新新状态。状态名改变只是程序控制；硬件配置、旧缓冲清理、稳定等待、读取恢复和迟到结果隔离仍要实际执行并验证。
\end{solution}
\paragraph*{第三章章末第 \ref{prob:v2-sdr-8} 题}
\begin{solution}
radio 年龄 0.4 s 过期，vision 年龄 0.1 s 有效，选择 vision。两路都不满足 $0\leq now-stamp\leq ttl$ 时输出 None；未来时间戳也不能被当作新鲜数据。这个判断要求可比较的同一时钟，不能直接混用不同主机墙钟。
\end{solution}
\paragraph*{第三章章末第 \ref{prob:v2-sdr-9} 题}
\begin{solution}
同步起点仍应为 19，序号 7、x=3.0 m、y=2.5 m；保存的频偏为 -125 Hz，采样率 8000 Hz、8 样本/符号、670 个复数。再生成 --corrupt 输入，展示 CRC 拒收。它验证已知频偏、恒定相位、整数样本延迟、固定帧长与本例噪声下的离线流程，未验证真实射频、未知频偏/符号率、时钟漂移、多径或连续流恢复。
\end{solution}

\section*{第四章：OpenCV 与图像处理基础}

\subsubsection*{随堂练习}
\paragraph*{随堂练习 \ref{ex:v2-cv-build}}
\begin{solution}
当前 foreach 按名称同时生成目标和源码路径；可把 version 改为 image，并同步将 src/version\_demo.cpp 改为 src/image\_demo.cpp。若想保留文件名，就为该目标明确指定原来的源码路径，并让 include/link 设置仍指向新目标。源文件名与目标并非语言要求必须相同，是本例循环采用了这个约定。重新配置后执行 \texttt{cmake --build build --target image\_demo} 和 \texttt{./build/image\_demo}。源码目录为工程当前目录，构建目录为其下 build。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-mat}}
\begin{solution}
b 改成 \texttt{a(cv::Rect(0,0,1,1))}，仍修改 b 的 (0,0)，输出保持 9 1。ROI 共享底层数据，clone 独立；访问矩形和像素必须在范围内。ROI 的行步长仍可能沿用原图，不保证裁下后连续。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-io}}
\begin{solution}
io 保留生成 input.png，把 imread 路径改成不存在的文件，在 empty 检查处返回 2；终端紧接着 \texttt{echo \$?} 核对。正确 viewer 窗口按 s 后生成 saved.png，尺寸仍为 48×32。空 Mat 没有有效像素，不能继续转换和访问。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-hsv}}
\begin{solution}
第二个 H=90 不属于两段红色，数量由 2 变成 1；第一个 S=0 低于下限 70，数量再变为 0。H/S/V 条件同时满足，颜色不能只按一个通道判断。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-threshold}}
\begin{solution}
首个固定阈值改 INV 后为 255 255 0，等于 127 属于反向模式的白色。只在 adaptiveThreshold 的 C 改为 -2，局部阈值从加权均值减 2 变成加 2，平坦区域更难入选；比较两份 adaptive.png 与非零计数。Otsu 示例保持原模式，应仍选出右半 400 像素。本次 OpenCV 4.6.0 的自适应非零数从 720 变成 80，判断还要结合输出图。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-filter}}
\begin{solution}
第一个操作改均值后，中心约为 $255/9$，存回 uchar 为 28；中值原来是 0。双边增大 sigmaColor 后，亮点和邻居的颜色差不再被强烈排斥，本次中心为 31，明显低于原来的 255；它不是无条件“保留边缘”。保边与去孤立噪点可能相互冲突，需对实际目标选择参数。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-morphology}}
\begin{solution}
7×7 核无法完全落入 5×5 方块，腐蚀后前景消失，再膨胀也不能恢复，非零数为 0。核与真实目标宽度比较，过大既去噪也去目标。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-contour}}
\begin{solution}
在 findContours 前另建 edges 并运行 Canny，分别打印原掩膜 200 像素、边缘像素和边缘外轮廓面积。本次 OpenCV 4.6.0 的边缘像素为56、外轮廓1、面积197；原掩膜连续面积为171，Canny 的梯度边缘会改变几何边界。轮廓面积、前景像素和边缘像素是三种量，不能预设相等。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-resize}}
\begin{solution}
最近邻从已有像素取值，圆边缘更锯齿，类别掩膜不插出新类别；AREA 在缩小时综合像素贡献，显示图通常更平滑。输出圆心为 (20,10)，图像尺寸40×20，不能再按原来 (40,20) 绘制。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-features}}
\begin{solution}
用二维仿射矩阵平移图像，再对两图分别 detectAndCompute，非空后以 Hamming、crossCheck 匹配；记录数量，并比较 trainIdx/queryIdx 对应关键点的横向偏移是否接近 +5、纵向是否接近0。本次匹配285个，其中222个偏移在(5,0)的2像素范围内。数量/距离会随裁剪、纹理和版本变化，可进一步用一致偏移或 RANSAC 检查几何，不能只看距离或数量。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-pipeline}}
\begin{solution}
面积下限 2000 大于两个轮廓的1711，最终保留0，但 mask/opened/closed/edges及外轮廓仍相同，annotated只是不再画框。生成视频正常读完为20帧；提前Esc则少于20，这也是有效退出。筛选只决定哪些几何对象保留，不应倒过来改变前面分割输入。
\end{solution}
\paragraph*{随堂练习 \ref{ex:v2-cv-bridge}}
\begin{solution}
把首个 toCvCopy 的目标改为 mono8，打印 channels 应为1；输入仍是 bgr8，实际进行灰度转换，红色像素为76。保留后面的 Header检查，输出秒/纳秒和frame不变。真实回调输入头由教学timer生成，在convert中沿用；若换实机输入，应使用相机采集头。只将标签改成mono8而保持CV\_8UC3数据，会导致编码与类型不符或错误解释，不能这样“转换”。
\end{solution}

检查实际目标的 include目录、链接库、源码路径、缓存中OpenCV位置，以及构建日志与版本输出。find\_package成功不意味着每个目标都已使用这些设置，也不能保证找的是你期望的安装。

600字节。ROI可能保留原图的行步长，行末仍隔着原图其他列；不能只按裁剪宽度连续读全部行。clone复制独立数据，对b共享修改影响a，对clone不影响；实际布局仍用isContinuous/step核对。

\paragraph*{第四章章末第 \ref{prob:v2-cv-4} 题}

两端都可能是红色，还需S/V条件；普通二值在等于阈值时输出0。自适应阈值按邻域均值/高斯加权值减C，C变大通常更易成为白色，变负则阈值升高；具体掩膜仍按实际输入查看。

\paragraph*{第四章章末第 \ref{prob:v2-cv-5} 题}
\begin{solution}
先试中值。开先腐蚀后膨胀，闭先膨胀后腐蚀；大核可能吞掉细目标或连上原本分离的区域，不能只以噪点数量评价。
\end{solution}
\paragraph*{第四章章末第 \ref{prob:v2-cv-6} 题}
\begin{solution}
边界点跨度19×9，连续面积171；栅格计数20×10=200。Canny提取灰度变化的边缘，可能与实心区域边界不同，轮廓模式和输入对象都要明确。
\end{solution}
\paragraph*{第四章章末第 \ref{prob:v2-cv-7} 题}
\begin{solution}
尺寸50×30，点变为(20,10)。类别掩膜通常需保留离散值，用最近邻；显示图可按缩放方向选择AREA/LINEAR等，平滑程度与用途不同。
\end{solution}
\paragraph*{第四章章末第 \ref{prob:v2-cv-8} 题}
\begin{solution}
本例默认WTA\_K=2用Hamming，其他配置查是否应Hamming2。先用匹配索引取对应关键点，再统计偏移/几何模型内点；重复纹理可以有低距离但错误位置，因此仍需几何一致性与有效匹配检查。
\end{solution}
\paragraph*{第四章章末第 \ref{prob:v2-cv-9} 题}
\begin{solution}
三通道可能是RGB、BGR或别的语义，必须查encoding。只改成mono8不转换像素会让类型、行步长或颜色解释不符，使用toCvCopy等做实际转换。处理后now是处理时刻，替换输入头会丢失采集时间，影响同步与融合；保留原Header并另记处理时延。
\end{solution}
\paragraph*{第四章章末第 \ref{prob:v2-cv-10} 题}
\begin{solution}
只用low掩膜后，H=179的右矩形消失，左矩形和孤立低H红点仍入选。预期mask1801、opened1800、closed1800，外轮廓1/保留1，连续面积1711。保存阶段图证明发生在颜色分割；面积筛选无法找回已被颜色条件排除的区域。
\end{solution}

\section*{第五章：神经网络与深度学习}

\subsection*{随堂练习}

\paragraph*{随堂练习 \ref{ex:v2-dl-fit}}
\begin{solution}
去掉扰动后，二阶与四阶都能拟合真正的二次规律，训练与验证误差接近浮点零；一阶仍有误差。模型容量较大不等于必然过拟合，仍须查看独立数据、划分与误差。四阶在原带扰动数据上插值了噪声，因此验证表现较差。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-env}}
\begin{solution}
激活后 sys.executable 应指向项目虚拟环境，版本组合为所装构建；未激活时可能导入失败，也可能找到另一套包，要记录实际结果。编辑器须选择该环境的解释器，不能因为终端已激活就假定 GUI 也自动使用它。使用 python -m pip 可将安装指向当前解释器。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-data}}
\begin{solution}
批量为 50、50、28，训练样本共 128，首批形状为 (50,1,28,28)/(50,)/(50,10)，验证与测试仍为 5000/10000。最后一批 \texttt{loss.item()} 是 28 个样本的均值，应乘 28 累加后除总样本；把三个批均值直接平均会提高小批量权重。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-ops}}
\begin{solution}
3 输入、2 窗口、步幅 2、无填充的空间尺寸为 1×1，最大值为 4、平均为 2。全 1 的互相关核、步幅 1 输出为 8/12/20/24。修改核改变加权和，修改池化步幅改变窗口位置与数量，二者不能混为一谈。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-shape}}
\begin{solution}
32→28→14→10→5，特征 (2,16,5,5)、展平 (2,400)，原 Linear256 无法接收。将其改为 Linear400 后分数为 (2,10)；两套结构的权重形状不同，不应用 28 输入的参数强行加载。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-grad}}
\begin{solution}
清零后梯度仍为 -16，学习率 0.05 更新为 w=0.8，损失 (1.6-4)²=5.76。若使用累加的 -32，则一步变为 1.6，损失约 0.64，这是改变了更新量，不证明不清零更好。backward 求梯度，step 才改参数。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-mode}}
\begin{solution}
p=0 时三种前向数值都为全 1，但训练+\texttt{no\_grad} 与 eval+\texttt{no\_grad} 不记录梯度，单独 eval 仍保留输入的梯度关系。engine 的 net.train(training) 控制层模式，\texttt{torch.set\_grad\_enabled}(training) 控制图记录；没有随机层时数值相同也不能合并这两个功能。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-train}}
\begin{solution}
小规模仅训练 128，完整训练55000，验证5000、测试10000。查看每轮 valid.loss 的最小值及保存条件，而非只看最后的 train.loss。本次固定CPU三轮验证损失约0.09170/0.07315/0.06032，选第三轮，最终测试准确率0.9853；这是实测示例，不是读者必须复现的分数。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-load}}
\begin{solution}
分类器第一层权重从120×256变成120×400，\texttt{load\_state\_dict} 会报告尺寸不匹配；恢复原结构才能正确加载。相同结构、参数、预处理与样本，推理应在数值容差内一致；归一化改变输入数值但不改变形状，可能不报错却改变分数或类别。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-device}}
\begin{solution}
CPU构建应记录版本中的+cpu和不可用CUDA；GPU还需记录驱动、CUDA构建、\texttt{is\_available}与设备名。train 先 LeNet().to(device) 再建优化器，engine 将x/y都移到device。可用设备需跑真实训练、保存、加载和同参数比较，误差满足相对1e-4/绝对1e-5；本次RTX3070Ti已验证，无设备的同学不能把静态检查当GPU运行。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-nms}}
\begin{solution}
0.681低于0.8，保留0/1/2；网络框和分数没有改变，只改变去重条件。不同类别应按类别分组或使用对应类别感知NMS；本例的单类nms会错误抑制高重叠但不同类的框。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-dl-deploy}}
\begin{solution}
分别用 --index 1/2 与独立 --output 路径，记录完整分数误差、(1,10)与类别，而非只比较最大索引。更改benchmark批量为8，报告每批T、每样本T/8、吞吐8/T及线程1。该计时不包含采集、预处理、队列、设备传输、后处理和显示，不能称为相机单帧延迟。
\end{solution}

\end{solution}

\section*{第六章：CUDA 与 GPU 加速}
\phantomsection
\addcontentsline{toc}{section}{第六章题解：CUDA 与 GPU 加速}
\subsubsection*{随堂练习}

\paragraph*{随堂练习 \ref{ex:v2-cuda-dependency}}
\begin{solution}
输入2/4/6/8时，阈值0/0/255/255，前缀和2/6/12/20。阈值每项只依赖本项输入，可分给独立线程；朴素前缀和保留此前累积状态，不能让线程读取尚未完成的前一结果。可用并行扫描重新组织，不能据此断言任何前缀和都无法并行。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-cuda-env}}
\begin{solution}
nvidia-smi能查询驱动与管理信息，找不到nvcc说明当前命令环境没有可定位的编译器，不说明驱动没装；检查容器包及PATH。驱动支持信息、编译器和框架运行依赖分开记录。旧截图中的Driver被取消，Toolkit11.8保留；是已有可用驱动的旧runfile背景，不是当前Ubuntu24.04要重复执行的命令。当前按开发包范围与apt模拟判断。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-cuda-build}}
\begin{solution}
实际nvcc路径、版本和设备计算能力应与构建输出对应；本次12.6.85、compute8.6，CMake架构86、nvcc目标\texttt{sm\_86}。-O2优化、-std=c++17选择标准、-arch选择架构、-o指定输出。单独编译相同vec\_add源码后对257/256运行应通过全部校验。新构建目录用于隔离缓存，不能用另一台设备的86硬套。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-cuda-memory}}
\begin{solution}
float为4字节，三个4096数组共49152字节（48KiB）；H2D32768、D2H16384，总搬运49152字节。主机a/b/c另在主机内存，不改变三个设备数组的字节数，也没有计入运行时上下文等其他GPU内存。程序实际输出应逐项对应。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-cuda-index}}
\begin{solution}
257/128为3块、384线程、127个跳过；257/256为2块、512线程、255个跳过。10/4为3块、12线程，索引10/11跳过。vecAdd里的if(i<n)防止尾部访问，检查全部c[i]验证索引与数值，首元素不能证明尾部正确；访问合法性再用memcheck等工具确认。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-cuda-shared}}
\begin{solution}
257/128为3块，每块128×4=512字节shared；输入i\%8，总和896，partial448/448/0。无效线程写0作为加法中性值，再参与全块同步；return会破坏协作。255不是二次幂，本实现步长不断减半会漏掉项，因此入口拒绝；这不是所有CUDA块大小都必须二次幂。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-cuda-error}}
\begin{solution}
launch由cudaGetLastError发现非法配置，execute先启动成功、再由cudaDeviceSynchronize发现断言，两者分别退出1。正常访问/共享/同步检查应零错误；工具模式要对应，memcheck不代替共享冲突检查，racecheck也不证明全部访问合法。故意memory模式由工具发现非法写入，本次还报告同步失败、返回9，属于被正确发现的负例；新进程vec\_add恢复正常，不继续坏上下文。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-cuda-timing}}
\begin{solution}
513个float一次上传/下载共2×513×4=4104字节，逐步往返6×513×4=12312字节。结果JSON应all\_checked=true，repeats5，四个时间为各自预热后的中位数。主机完整区间含指定传输、启动与等待，事件只包三个核；分配、初始化、输入生成、校验在外，更没有相机采集、排队或真实前后处理。kernel\_ms不能当相机单帧响应。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-cuda-deploy}}
\begin{solution}
三个算子合计3ms，各步上传下载共六次、每次2ms，因此15ms；统一两次传输为7ms。假设没有传输重叠，也忽略启动调度；真实pipeline仍有三次启动和同步等成本。前章比较数值/输入限制，本章比较同输入的处理开销，都只是部署的一部分；还要核对目标运行栈、模型版本、预处理/后处理与真实端到端响应。
\end{solution}

\paragraph*{随堂练习 \ref{ex:v2-cuda-boundary}}
\begin{solution}
本次正常查询一个设备并实际分配；隐藏CUDA设备时cudaGetDeviceCount报告无可用设备、退出1，CPU小程序仍运行，恢复默认可见性后查询成功。变量只限制当前应用，管理工具可能仍看到物理GPU，不能替代应用内访问。缺硬件或透传时，阅读/CPU/静态编译与GPU执行/工具/计时分开记录，未运行项不能写通过。
\end{solution}

\subsubsection*{章末习题}
\paragraph*{第六章章末习题 \ref{prob:v2-cuda-dependency}}
\begin{solution}
阈值仅依赖对应输入，朴素前缀和依赖先前累积/多个输入。CUDA线程是执行模型，不与物理核心一一固定对应；块调度顺序不保证，不能假定低编号先完成。
\end{solution}

\paragraph*{第六章章末习题 \ref{prob:v2-cuda-env}}
\begin{solution}
分别是驱动管理、编译工具、框架构建依赖和应用实际加载的运行时。版本不同可正常工作，也可能不兼容，应核对具体支持条件并运行，而非只比较数字。本次runtime12060、driver API13040实际通过。
\end{solution}

\paragraph*{第六章章末习题 \ref{prob:v2-cuda-memory}}
\begin{solution}
设备三个数组6144字节，上传4096、下载2048；主机数组另占主机内存，不能把设备数组翻倍。不包含其他分配和运行时开销。
\end{solution}

\paragraph*{第六章章末习题 \ref{prob:v2-cuda-index}}
\begin{solution}
3块、768线程，尾块1个有效线程，255个跳过。首项正确只证明首项，需全部输出校验和访问检查；越界有时不立刻崩溃。
\end{solution}

\paragraph*{第六章章末习题 \ref{prob:v2-cuda-shared}}
\begin{solution}
Shared由同一块线程共享，local是线程私有访问范围、通常位于设备内存。补零不改变加法结果且让无效线程继续同步；二次幂保证本算法每轮整齐配对。加法条件可只让一部分线程写，屏障仍应全块按要求参与；块间不能用它同步。
\end{solution}

\paragraph*{第六章章末习题 \ref{prob:v2-cuda-error}}
\begin{solution}
cudaDeviceSynchronize等同步检查发现设备断言，启动检查不足。memcheck查访问，racecheck查共享读写冲突，synccheck查同步，覆盖范围不同。工具发现的故意负例与正常零错误记录要分开。
\end{solution}

\paragraph*{第六章章末习题 \ref{prob:v2-cuda-timing}}
\begin{solution}
不能，0.01ms不含传输，0.8ms也可能没有采集和前后处理。CUDA提交异步，主机时钟只量提交可能严重低估；计时前排除前序未完成工作，终点必须等待所测工作完成。注明设备、规模、预热、重复、结果与排除项。
\end{solution}

\paragraph*{第六章章末习题 \ref{prob:v2-cuda-reduction}}
\begin{solution}
不必然。浮点加法不满足精确结合律，树形与串行顺序可能不同。先用工具检查访问/同步，用相同数据的高精度参考与适当绝对/相对容差检查误差；误差大小要结合数据范围、算法与用途，不能拿舍入解释任意错误。
\end{solution}

\paragraph*{第六章章末习题 \ref{prob:v2-cuda-practice}}
\begin{solution}
提交现场长度/块大小、向上取整与字节手算、全部输出校验；共享归约提交partial及CPU总和，块大小满足本算法约束。记录正常工具零错误与独立负例报告；pipeline四个时间和搬运量须用相同输入及正确结果解释。保存系统/编译器/架构/运行库和实际命令；无设备只完成CPU或静态检查时，明确剩余运行项，不能靠样例日志代替本机验证。
\end{solution}

\section*{第七章：相机与成像原理}
\phantomsection
\addcontentsline{toc}{section}{第七章题解：相机与成像原理}
\subsubsection*{随堂练习}

\paragraph*{练习 \ref{ex:v2-camera-sensor}}
\begin{solution}
记录设备完整型号、数据表版本或来源，以及最大分辨率、像元尺寸（通常为微米）、快门类型；例如记录格式可以是“型号：实际型号；分辨率：数据表值；像元尺寸：数据表值；快门：global/rolling/未知”。分辨率不等于物理感光面尺寸，同属 CMOS 也不能推断快门类型。缺失字段如实标未知。
\end{solution}

\paragraph*{练习 \ref{ex:v2-camera-exposure}}
\begin{solution}
从 f/4 收到 f/5.6，进光量约减半。保持亮度和增益不变，曝光应从 1 ms 延长到约 2 ms；若按标称比值精算，为 $(5.6/4)^2\approx1.96$ ms。相同图像运动速度下，曝光内位移也近似加倍，运动模糊风险增加。
\end{solution}

\paragraph*{练习 \ref{ex:v2-camera-noise}}
\begin{solution}
泊松模型下标准差为 $\sqrt{900}=30$，相对噪声为 $30/900\approx3.33\%$。补光可以增加收到的光子数，改善此模型下的相对散粒噪声；数字增益只是同时放大已有信号与噪声，不能提供额外光子信息。
\end{solution}

\paragraph*{练习 \ref{ex:v2-camera-format}}
\begin{solution}
像素数为 $1280\times720=921600$。Bayer8 为 921600 字节，BGR8 为 2764800 字节。文件还可能包含头部、元数据、行填充，或使用压缩编码，因此文件长度不一定等于原始像素区长度。
\end{solution}

\paragraph*{练习 \ref{ex:v2-camera-gamma}}
\begin{solution}
当 $\gamma=1$，映射成为 $y=x$。对整数范围 0 到 255，使用本章构表公式并 round 后应逐项等于输入，可直接检查：
\begin{tpython}
gamma = 1.0
lut = [round(255*(i/255)**(1/gamma)) for i in range(256)]
assert lut == list(range(256))
\end{tpython}
也可运行 format\_gamma.py --gamma 1，预期 identity=true；改为0.5时 LUT[128]=64，暗部压暗。饱和像素的纹理已经丢掉，提亮不能恢复。
\end{solution}

\paragraph*{练习 \ref{ex:v2-camera-dof}}
\begin{solution}
代入焦距 16 mm、光圈数 8、弥散圆 0.01 mm，得 $H=16^2/(8\times0.01)+16=3216$ mm。与光圈数 4 时的 6416 mm 比较，收小光圈使超焦距减小；在同焦距、同对焦距离与清晰度判据下，通常使景深增加。N=8、s=2000时近界约1234.57、远界约5263.16 mm；s=7000时远界分母不为正，far=null表示无穷。实际极小光圈还需考虑衍射，并且收光圈减少进光，可能迫使曝光变长。
\end{solution}

\paragraph*{练习 \ref{ex:v2-camera-motion}}
\begin{solution}
图像速度为 800 pixel/s，要求位移不超过 1 pixel，则曝光时间满足 $t\le1/800=0.00125$ s，即 1.25 ms。保持曝光时间和运动速度不变，仅提高增益不会减少位移；增益只可能在亮度允许时帮助选择更短的曝光。首末行差6 ms对应4.8 pixel跨行位置差；曝光积分造成模糊，读出时差造成形变，缩短前者不保证后者随之减少。
\end{solution}

\paragraph*{练习 \ref{ex:v2-camera-lens}}
\begin{solution}
小角度与相同成像比例近似下，宽度为 $20\times12/8=30$ pixel。条件包括目标尺寸与姿态、距离、传感器像元尺寸、输出分辨率和裁剪缩放方式均不变；离轴畸变或较近拍摄时，简单比例可能不够准确。裁剪再放大只是重采样已有信息，不能增加传感器收到的真实目标细节。
\end{solution}

\paragraph*{练习 \ref{ex:v2-camera-calibrate}}
\begin{solution}

\paragraph*{随堂练习 9.3}
\begin{solution}
列向量约定下取
\[
R=\begin{bmatrix}0&-1&0\\1&0&0\\0&0&1\end{bmatrix},\quad
p=\begin{bmatrix}0\\2\\3\end{bmatrix},\quad
t=\begin{bmatrix}1\\0\\0\end{bmatrix}.
\]
于是 $Rp+t=(-1,0,3)^T$。代入 $R^T(q-t)$ 应恢复原点坐标 (0,2,3)。

\paragraph*{随堂练习 9.4}
\begin{solution}
保留原三维点顺序，只交换两项二维观测，然后重新求位姿并对所有点计算重投影 RMS。通常误差会明显增大，也可能返回不合理位姿或失败；具体值受求解器影响。成功返回只表示算法给出了结果，仍须核对点序、残差、正深度与位姿范围，不能把布尔返回值当成数据正确的证明。
\end{solution}

\paragraph*{随堂练习 9.5}
\begin{solution}
三个差值变为 2、2、8，因此 $t=(2+2+8)/3=4$。预测为 [4,5,6]，观测为 [2,3,10]，残差平方和为 $2^2+2^2+(-4)^2=24$。平方损失对大残差赋予很大代价，导致异常点把解从 2 拉到 4；可考虑异常点检测或适当的鲁棒损失。
\end{solution}

\paragraph*{随堂练习 9.6}
\begin{solution}

\end{solution}

\paragraph*{随堂练习 9.7}
\begin{solution}
\texttt{numpy.linalg.qr(M)} 返回 Q 和上三角因子 U，应检查 \texttt{Q @ U} 重建 M。通常 Q 不等于原来的旋转 R，U 也不等于原内参 K，因为原模型是 K 在左、R 在右。可以打印两个差值矩阵或使用 allclose 验证，而不能只看到一个正交矩阵就称其为相机旋转。
\end{solution}

\paragraph*{随堂练习 9.8}
\begin{solution}
该矩阵本身是反射矩阵，未修正的 $UV^T$ 行列式为 -1。反射会改变坐标系手性，三维适当旋转必须满足正交性且行列式为 +1。按正文公式加入行列式修正后得到适当旋转；本例奇异值相同，最近旋转可能不唯一，不应要求某个固定的矩阵元素结果。
\end{solution}

\paragraph*{随堂练习 9.9}
\begin{solution}
例如令目标点为 $Q=PR^T+t$，其中 P 按行存放点，R 为绕 z 轴 90° 的旋转。只用质心差估计平移会得到 $(1/3,2,3)$，不能恢复原来的 $(1,2,3)$；三点残差平方和为 $8/3$。旋转改变点集相对质心的方向，单一平移无法补偿，需同时估计 R 和 t。
\end{solution}

\paragraph*{随堂练习 9.10}
\begin{solution}
角度改为 $-\pi/2$ 时，x 轴单位向量变为 $(0,-1,0)$，绕 z 轴的方向与正角相反。旋转矩阵的元素不能自由变化：需同时满足 $R^TR=I$ 和 $\det R=1$。逐元素相加通常破坏这些约束，应按统一约定用旋转复合或李代数扰动。
\end{solution}

\subsubsection*{随堂练习}

\paragraph*{随堂练习 11.1}
\begin{solution}
已有路径但没有速度时，先检查控制器是否激活、是否收到路径、局部代价地图与 TF 是否可用，以及进度/目标检查和下游速度接口。没有位姿时，先从定位输入、时间戳、TF 连通性和定位节点状态查起；没有坐标变换基础时，反复重算路径不能解决问题。
\end{solution}

\paragraph*{随堂练习 11.2}
\begin{solution}
停止原发布程序后，把 x 改为 2 再启动，tf2\_echo 应看到 x 平移为 2，y、z 为 0。不要让两个发布者同时发布同一个子坐标系。真实 map 到 odom 的变换用于随定位结果修正累计漂移，通常随时间变化；固定演示值不能长期替代定位输出。
\end{solution}

\paragraph*{随堂练习 11.3}
\begin{solution}
原例格心相对原点为 (0.525,1.025) m，加上新原点 (-2,-1)，得到 (-1.475,0.025) m。分辨率与栅格宽高共同决定地图覆盖的物理尺寸，例如宽 W 格时宽度为 $W\times resolution$。本题假定原点偏航为零，存在旋转时还需先旋转再平移。
\end{solution}

\paragraph*{随堂练习 11.4}
\begin{solution}
A 到 C 的直达代价改为 2，经 B 的代价仍为 $1+2=3$，所以最短距离为 2，走直接边。最少边只统计经过多少条边，最低代价则累加边权；原例直接边代价 5 时，一条边反而不如两条边的总代价 3。
\end{solution}

\paragraph*{随堂练习 11.5}
\begin{solution}
加入以下断言：
\begin{tpython}
assert fallback(["Failure", "Failure"]) == "Failure"
\end{tpython}
基础 Fallback 只传播子项状态；重试上限应由上层任务编排、重试装饰节点或明确的恢复策略决定，同时设超时与最终失败出口。不能由每个底层模块各自无限重试。
\end{solution}
